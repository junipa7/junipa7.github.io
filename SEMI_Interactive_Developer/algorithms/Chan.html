Chan's Convex Hull 알고리즘

평면 상의 n개 점으로부터 Graham Scan과 Jarvis March를 결합하여 O(n log h) 속도로 Convex Hull(볼록 껍질)을 구하는 기하학적 최적화 알고리즘입니다.

Streaming KPIDeveloper

개발 기능 요약

설비 공정 파라미터(온도, 압력 등)의 다차원 분포를 분석하여 정상 가동 범위(Operating Envelope)를 산출하고 극단적인 이상치(Outlier)를 판별할 때 사용됩니다.

핵심 로직: \(m = 2^{2^t}\) 크기 그룹 분할 후, Graham Scan 적용 후 Jarvis March 접선 탐색 및 병합

알고리즘 상세 개요

Convex Hull (볼록 껍질)의 개념

2차원 또는 다차원 공간에 흩어져 있는 여러 점들을 모두 감싸는 가장 작은 볼록한 다각형(또는 다면체)을 의미합니다. 전산 기하학(Computational Geometry)에서 가장 기본적이면서도 중요한 개념입니다.

가장 직관적인 비유는 '고무줄 비유(Rubber Band Analogy)'입니다. 널빤지 위에 여러 개의 못(데이터 점)이 박혀 있다고 상상해 보세요. 커다란 고무줄을 팽팽하게 늘려서 모든 못을 바깥쪽에서 감싸도록 놓았을 때, 고무줄이 수축하면서 바깥쪽 못들에 걸쳐 만들어지는 형태가 바로 이 못들의 Convex Hull입니다.

기하학적 및 수학적 정의

  • 볼록(Convex)의 의미: 다각형 내부에 있는 임의의 두 점을 골라 선분으로 연결했을 때, 그 선분이 다각형의 경계선 밖으로 전혀 나가지 않는 형태를 말합니다.
  • 최소성(Minimality): 점 집합 S를 포함하는 볼록 다각형은 무수히 많을 수 있지만, Convex Hull은 그 중에서 '가장 작은(면적이 최소인)' 다각형입니다.
  • 정점(Vertex): Convex Hull의 꼭짓점을 이루는 점들을 '극단점(Extreme Points)'이라고 하며, 이들은 원래 점 집합 S에 속해 있는 데이터들 중 가장 외곽에 위치한 데이터들입니다.

주요 탐색 알고리즘 비교

  • Jarvis March (선물 포장 알고리즘, Gift Wrapping): 가장 왼쪽 점에서 시작해 반시계 방향으로 선물을 포장하듯 다음 점을 찾아나갑니다. 시간 복잡도: \(O(nh)\) (n: 전체 점, h: 껍질 정점 수)
  • Graham Scan (그레이엄 스캔): 각도 기준으로 전체 정렬(\(O(n \log n)\)) 후 스택을 사용하여 오목점을 제거하며 껍질을 완성합니다.
  • Chan's Algorithm (찬의 알고리즘): 데이터를 크기 m인 그룹으로 나누어 Graham Scan을 수행한 후, Jarvis March 방식으로 병합하여 \(O(n \log h)\)라는 이론적 최적 복잡도를 달성합니다.

개발 DFD

상세 작동 단계

  1. 그룹 분할 (Partitioning)

    전체 점 집합 P를 크기가 m인 r개의 그룹으로 나눕니다.

    • 그룹의 수: \(r = \lceil n/m \rceil\)
    • 수식: \(P = \{P_1, P_2, ..., P_r\}\) 이며, 각 \(|P_i| \le m\) 입니다.
  2. 개별 Convex Hull 생성 (Graham Scan)

    각 그룹 P_i에 대해 Graham Scan 알고리즘을 적용하여 각각의 작은 볼록 껍질 CH_i를 구합니다. 이 과정의 시간 복잡도는 그룹당 O(m log m)이 소요되므로 전체적으로 \(O(n \log m)\)입니다.

  3. Jarvis March를 이용한 병합 (Gift Wrapping)

    가장 왼쪽에 있는 점 P_i에서 시작하여, 전체 껍질의 다음 정점 P_{k+1}을 찾습니다. 이때 각 그룹의 껍질(CH_i)과 현재 점(P_k) 사이의 접선(Tangent)을 이진 탐색으로 찾습니다.

    • 접점 탐색: \(P_k\)에서 각 \(CH_i\)로의 접선을 찾는 시간은 \(O(\log m)\)입니다.
    • 다음 정점 결정: r개의 그룹 중에서 가장 외곽에 있는 점을 고르는 과정은 \(O(r \log m)\)입니다.
    • 이 과정을 h번 반복하므로 최종 병합 시간은 \(O(h \cdot (n/m) \log m)\)입니다.
  4. 반복적 파라미터 최적화 (Iterative Strategy)

    우리는 h를 미리 알 수 없으므로, m을 \(2^{2^t}\) (t=1,2,...) 순으로 기하급수적으로 키우며 위 과정을 반복합니다.

    \(\sum_{t=1}^{\log\log h} n \cdot \log(2^{2^t}) = \sum_{t=1}^{\log\log h} n \cdot 2^t = O(n \log h)\)

실시간 설비 OEE 적용 시나리오

  • 설비 파라미터 경계면(Envelope) 분석: OEE 성능 효율 계산 시, 단순히 평균값만 분석하는 대신 Chan's Algorithm을 사용하여 '정상 가동 범위(Normal Operating Zone)'의 다차원 기하학적 경계를 확정할 수 있습니다. 경계 밖의 데이터는 이상 센서 드리프트 등으로 판별하여 가동 손실 원인 추적에 사용합니다.
  • 분산 데이터 요약: 여러 대의 설비(r개)에서 각각 계산된 부분 Convex Hull(CH_i) 정보만 중앙 서버로 보내면, 서버는 전체 원시 데이터를 전송받을 필요 없이 접선 계산만으로 라인 전체의 공정 경계를 즉시 합성할 수 있습니다.

KLL & Chan 기반 설비 효율 분석 통합 로직 및 아키텍처

설비 상태 및 효율에 기반하여 대규모 설비 데이터 스트림을 처리하기 위해, Chan's Algorithm(기하학적 경계 산출)과 KLL Sketch(통계적 분포 추정)를 결합한 통합 이상치 제거 및 성능 지표 산출 로직을 설계합니다. 이 통합 로직은 다차원 데이터의 경계(Hull)와 단일 변수의 분포(Quantile)를 모두 고려하여 정교하게 이상치를 필터링하고, 최종적으로 정확한 성능 효율(Performance Efficiency)을 계산하는 데 초점을 맞춥니다.

1. 통합 분석 로직 개요

  • E10 RUN Filter: 설비 상태가 'PRD(Production)'인 유효 가동 시간 데이터만 추출합니다.
  • Chan Engine: 다차원 공정 파라미터(예: 온도 vs 압력)의 기하학적 정상 가동 범위(Operating Envelope)를 계산하여 외곽점(Outlier)을 감지합니다.
  • KLL Engine: 성능 효율의 핵심 지표인 Cycle Time(CT)에 대한 실시간 백분위수(P99, Median)를 추정합니다.
  • 이중 이상치 제거: 신규 데이터 x에 대해 기하학적 정상 가동 범위 내부에 있고, Cycle Time이 P99 임계값보다 작은 경우에만 '정상 데이터 D_clean'으로 판별합니다.
    $$D_{clean} = \{x \in D \mid (isInside(H, x.v)) \land (x.CT < \hat{q}_{0.99})\}$$
  • E79 성능 효율 산출: 정상 데이터 D_clean의 KLL 추정 중위수(Median CT, $\hat{q}_{0.50}$)를 실제 속도로 사용하여 성능가동율을 산출합니다.
    $$\text{성능가동율} = \frac{\text{Theoretical Cycle Time (TCT)}}{\hat{q}_{0.50}} \times 100(\%)$$

2. 설비 효율 분석 시스템 아키텍처

  • Edge Network (데이터 수집): 설비(PLC/GEM)로부터 SECS/GEM 프로토콜을 통해 실시간 상태(E10), 공정 변수, Cycle Time을 Edge Gateway가 수집하여 전송합니다.
  • Stream Processor (실시간 분석 계층): 스트림 처리 엔진 내에서 Chan Engine과 KLL Engine이 각각 기하학적 경계와 통계적 분포를 모델링하고, 통합 필터를 통해 스파이크성 에러와 가짜 데이터를 차단합니다.
  • MES DB / RDBMS: 정제된 성능 지표, E10 상태 로그, 최신 요약본(Convex Hull 정점 및 KLL Sketch 요약본)을 안정적으로 저장합니다.
  • OEE Calculator & Dashboard (시각화 계층): 정제된 실제 속도와 SEMI Product Time 기반의 표준시간(Standard Time)을 비교하여 종합설비효율(OEE)을 산출하고 운영자에게 실시간으로 공유합니다. (양품율은 배제하고 시간가동율과 성능가동율의 곱으로만 OEE 계산)
