핵심 로직: 용량 초과 시 Level i의 버퍼를 정렬하고, 동전 던지기 b \in \{0,1\}에 따라 홀수/짝수 번째 값만 상위 Level i+1로 보내 가중치 2배 부여

알고리즘 상세 개요

KLL (Karnin-Lang-Liberty) Sketch의 개념

KLL 알고리즘은 스트리밍 데이터에서 Quantiles(분위수)를 추정하기 위해 설계된 최신 알고리즘입니다. Apache DataSketches 라이브러리 등에 포함되어 실무에서 대용량 모니터링 분석에 널리 쓰입니다.

수억 개의 데이터가 실시간으로 들어올 때, 모든 데이터를 정렬하여 "상위 1% 값"이나 "중간값(Median)"을 찾는 것은 메모리상 불가능합니다. KLL은 아주 적은 메모리만 사용하면서도 매우 높은 정확도로 이 값들을 추정합니다.

KLL 알고리즘의 구조: 계층적 버퍼 (Hierarchical Buffers)

KLL은 여러 개의 Level(H)로 구성된 버퍼 구조를 가집니다. 각 레벨 i는 용량 k_i를 가지며, 레벨이 올라갈수록 데이터의 '가중치'는 2배씩 증가합니다.

  • Level 0: 원래의 데이터(가중치 1)가 들어오는 곳입니다.
  • Level i: 가중치가 \(2^i\)인 데이터들이 저장됩니다.

개발 DFD

상세 작동 단계

Compaction은 특정 레벨의 버퍼가 가득 찼을 때, 데이터를 상위 레벨로 보내면서 크기를 줄이는 핵심 프로세스입니다.

  1. 트리거 (Trigger)

    레벨 i의 데이터 개수가 미리 정의된 용량 \(k_i\)를 초과하면 압축이 시작됩니다.

  2. 정렬 (Sorting)

    해당 레벨의 버퍼에 있는 데이터들을 오름차순으로 정렬합니다.

    \(X = \{x_1, x_2, ..., x_n\} \quad (x_1 \le x_2 \le ... \le x_n)\)
  3. 선택 및 제거 (Selection & Eviction)

    정렬된 데이터 중 홀수 번째 또는 짝수 번째 데이터만 선택하여 상위 레벨(i+1)로 보냅니다. 이때 선택은 무작위(Random)로 결정하여 편향(Bias)을 방지합니다.

    • 동전 던지기(\(b \in \{0,1\}\))를 통해 결정:
    • b=0이면: \(\{x_2, x_4, x_6, ...\}\) 를 상위 레벨로 전달
    • b=1이면: \(\{x_1, x_3, x_5, ...\}\) 를 상위 레벨로 전달
    • 선택되지 않은 나머지 절반의 데이터는 메모리에서 완전히 삭제됩니다.
  4. 가중치 갱신 (Weight Update)

    상위 레벨로 올라간 데이터는 이제 이전보다 2배의 가중치를 갖게 됩니다.

    Level i의 데이터 2개가 Level i+1의 데이터 1개로 대체되지만, 가중치가 \(2^i\)에서 \(2^{i+1}\)로 변하므로 전체 통계적 분포(Sum of Weights)는 유지됩니다.

수학적 오차 보장 및 분석

수식적 이해와 오차 보장

KLL 알고리즘의 가장 큰 장점은 메모리 사용량과 오차 범위 사이의 관계를 수학적으로 증명했다는 점입니다.

  • 레벨별 용량 설정 (\(k_i\))

    메모리를 효율적으로 쓰기 위해 상위 레벨로 갈수록 버퍼 크기를 기하급수적으로 줄입니다.

    \(k_i \approx k \cdot c^{H-i}\)

    (여기서 k는 전체 파라미터, c는 1보다 작은 상수(약 2/3)입니다.)

  • 오차 범위 (\(\epsilon\))

    사용자가 허용하는 오차 \(\epsilon\)에 대해, KLL Sketch가 필요한 메모리 공간 M은 다음과 같습니다.

    \(M = O(1/\epsilon \cdot \log(\log 1/\epsilon))\)

    이는 기존의 다른 알고리즘(예: GK Array)보다 훨씬 적은 메모리로도 동일한 정확도를 낼 수 있음을 의미합니다.

실시간 설비 OEE 적용 시나리오

  • 실시간 OEE 모니터링: 설비에서 발생하는 수백만 건의 Cycle Time 데이터를 DB에 다 쌓지 않고도, 메모리 내에서 즉시 95% 신뢰 구간의 성능 지표를 산출할 수 있습니다.
  • 이상치(Outlier) 필터링: 성능 효율을 계산할 때, 비정상적으로 길게 측정된 Cycle Time을 KLL의 분위수 기반 필터링(예: 상위 99% 제외)을 통해 자동 제거하여 데이터의 정밀도를 높일 수 있습니다.
  • 분산 데이터 통합: 여러 대의 설비(Equipment)에서 각각 생성된 KLL Sketch를 중앙 서버로 보내기만 하면, 추가 연산 없이 '병합(Merge)'하여 라인 전체의 통합 통계 데이터를 얻을 수 있습니다.

KLL & Chan 기반 설비 효율 분석 통합 로직 및 아키텍처

설비 상태 및 효율에 기반하여 대규모 설비 데이터 스트림을 처리하기 위해, Chan's Algorithm(기하학적 경계 산출)과 KLL Sketch(통계적 분포 추정)를 결합한 통합 이상치 제거 및 성능 지표 산출 로직을 설계합니다. 이 통합 로직은 다차원 데이터의 경계(Hull)와 단일 변수의 분포(Quantile)를 모두 고려하여 정교하게 이상치를 필터링하고, 최종적으로 정확한 성능 효율(Performance Efficiency)을 계산하는 데 초점을 맞춥니다.

1. 통합 분석 로직 개요

  • E10 RUN Filter: 설비 상태가 'PRD(Production)'인 유효 가동 시간 데이터만 추출합니다.
  • Chan Engine: 다차원 공정 파라미터(예: 온도 vs 압력)의 기하학적 정상 가동 범위(Operating Envelope)를 계산하여 외곽점(Outlier)을 감지합니다.
  • KLL Engine: 성능 효율의 핵심 지표인 Cycle Time(CT)에 대한 실시간 백분위수(P99, Median)를 추정합니다.
  • 이중 이상치 제거: 신규 데이터 x에 대해 기하학적 정상 가동 범위 내부에 있고, Cycle Time이 P99 임계값보다 작은 경우에만 '정상 데이터 D_clean'으로 판별합니다.
    $$D_{clean} = \{x \in D \mid (isInside(H, x.v)) \land (x.CT < \hat{q}_{0.99})\}$$
  • E79 성능 효율 산출: 정상 데이터 D_clean의 KLL 추정 중위수(Median CT, $\hat{q}_{0.50}$)를 실제 속도로 사용하여 성능가동율을 산출합니다.
    $$\text{성능가동율} = \frac{\text{Theoretical Cycle Time (TCT)}}{\hat{q}_{0.50}} \times 100(\%)$$

2. 설비 효율 분석 시스템 아키텍처

  • Edge Network (데이터 수집): 설비(PLC/GEM)로부터 SECS/GEM 프로토콜을 통해 실시간 상태(E10), 공정 변수, Cycle Time을 Edge Gateway가 수집하여 전송합니다.
  • Stream Processor (실시간 분석 계층): 스트림 처리 엔진 내에서 Chan Engine과 KLL Engine이 각각 기하학적 경계와 통계적 분포를 모델링하고, 통합 필터를 통해 스파이크성 에러와 가짜 데이터를 차단합니다.
  • MES DB / RDBMS: 정제된 성능 지표, E10 상태 로그, 최신 요약본(Convex Hull 정점 및 KLL Sketch 요약본)을 안정적으로 저장합니다.
  • OEE Calculator & Dashboard (시각화 계층): 정제된 실제 속도와 SEMI Product Time 기반의 표준시간(Standard Time)을 비교하여 종합설비효율(OEE)을 산출하고 운영자에게 실시간으로 공유합니다. (양품율은 배제하고 시간가동율과 성능가동율의 곱으로만 OEE 계산)
