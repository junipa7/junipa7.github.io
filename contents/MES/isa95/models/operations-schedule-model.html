이 문서는 ANSI/ISA-95를 기반으로 MES/MOM 시스템 설계를 학습하기 위한 교육용 해설입니다. 공식 표준 조항을 대체하지 않으며, 실제 프로젝트에서는 최신 ISA-95 문서, 고객 URS, 사이트 표준, ERP/PLC/SCADA 연동 규격을 함께 검토해야 합니다.

1. 모델 목적

계획된 작업 요청을 언제, 어디서, 어떤 순서로 실행할지 표현합니다.

ISA-95 모델은 화면 이름을 정하는 용도가 아니라 시스템 사이의 데이터 계약을 정하는 기준입니다. 같은 설비, 자재, 작업 요청을 ERP, MES, SCADA가 서로 다르게 해석하면 통합 비용이 커지므로 객체의 경계와 관계를 먼저 맞춰야 합니다.

2. 핵심 구조

객체역할수업식 해설
Operations Request작업 요청상위 계획에서 내려온 실행 요청입니다.
Operations Schedule운영 일정시간과 순서를 포함한 실행 계획입니다.
Segment Request세그먼트 요청작업을 세부 operation 단위로 나눈 항목입니다.
Schedule Response스케줄 응답가능/불가능, 예정 시간, 제약 사유를 반환합니다.

3. 모델 DFD

단계의미모델링 포인트
1. Operations Request상위 개념 또는 입력 객체입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
2. Operations Schedule관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
3. Operations Segment Request관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
4. Dispatchable Work관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
5. Schedule Response하위 시스템이나 통합 메시지가 사용하는 결과입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.

5. 설계 규칙

규칙 ID설계 규칙검증 방법
MR-01스케줄은 요청, 자원, 세그먼트, 시간 구간을 연결해야 합니다.모델 validation, master data governance, integration contract test로 검증
MR-02계획 변경은 이전 schedule을 보존하고 새 revision으로 관리합니다.모델 validation, master data governance, integration contract test로 검증
MR-03Dispatch 전에는 최신 shopfloor 상태로 재검증합니다.모델 validation, master data governance, integration contract test로 검증

6. 통합 관점

ERP계획, 품목, 주문, 원가와 연결되는 상위 기준정보를 제공합니다.
MES/MOM실행 상태, schedule, performance, genealogy를 관리합니다.
SCADA/PLC실제 설비 상태와 공정 데이터를 이벤트로 제공합니다.

8. 운영 체크리스트

  • 객체 ID와 외부 시스템 ID 매핑표가 있다.
  • 기준정보 owner system과 변경 승인 절차가 명확하다.
  • 모델 변경 시 영향받는 schedule, request, performance를 조회할 수 있다.
  • 통합 메시지 실패를 재처리할 수 있다.
  • 과거 실적을 당시 모델 revision 기준으로 해석할 수 있다.
