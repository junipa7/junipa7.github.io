이 문서는 ANSI/ISA-95를 기반으로 MES/MOM 시스템 설계를 학습하기 위한 교육용 해설입니다. 공식 표준 조항을 대체하지 않으며, 실제 프로젝트에서는 최신 ISA-95 문서, 고객 URS, 사이트 표준, ERP/PLC/SCADA 연동 규격을 함께 검토해야 합니다.

1. 모델 목적

작업자, 역할, 자격, 숙련도, 교육 이력을 구조화하여 누가 어떤 작업을 수행할 수 있는지 판단합니다.

ISA-95 모델은 화면 이름을 정하는 용도가 아니라 시스템 사이의 데이터 계약을 정하는 기준입니다. 같은 설비, 자재, 작업 요청을 ERP, MES, SCADA가 서로 다르게 해석하면 통합 비용이 커지므로 객체의 경계와 관계를 먼저 맞춰야 합니다.

2. 핵심 구조

객체역할수업식 해설
Person작업자실제 작업 또는 승인을 수행하는 사람입니다.
Role역할Operator, Engineer, Quality Approver처럼 권한과 책임을 묶습니다.
Qualification자격제품, 공정, 설비별 수행 가능성을 나타냅니다.
Shift근무가용 시간과 근무 상태를 표현합니다.

3. 모델 DFD

단계의미모델링 포인트
1. Person상위 개념 또는 입력 객체입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
2. Role관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
3. Qualification관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
4. Shift관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
5. Assignment하위 시스템이나 통합 메시지가 사용하는 결과입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.

5. 설계 규칙

규칙 ID설계 규칙검증 방법

MR-02자격은 유효기간과 level을 함께 가져야 합니다.모델 validation, master data governance, integration contract test로 검증
MR-03승인 권한과 작업 권한은 분리할 수 있어야 합니다.모델 validation, master data governance, integration contract test로 검증

6. 통합 관점

ERP계획, 품목, 주문, 원가와 연결되는 상위 기준정보를 제공합니다.
MES/MOM실행 상태, schedule, performance, genealogy를 관리합니다.
SCADA/PLC실제 설비 상태와 공정 데이터를 이벤트로 제공합니다.

7. 테스트 시나리오

테스트 ID시나리오기대 결과
TC-01자격 보유자 작업 시작객체 관계, ID 매핑, revision, 통합 메시지가 설계와 일치해야 합니다.
TC-02자격 만료자 차단객체 관계, ID 매핑, revision, 통합 메시지가 설계와 일치해야 합니다.
TC-03승인 권한 검증객체 관계, ID 매핑, revision, 통합 메시지가 설계와 일치해야 합니다.
TC-04근무시간 외 배정 경고객체 관계, ID 매핑, revision, 통합 메시지가 설계와 일치해야 합니다.

8. 운영 체크리스트

  • 객체 ID와 외부 시스템 ID 매핑표가 있다.
  • 기준정보 owner system과 변경 승인 절차가 명확하다.
  • 모델 변경 시 영향받는 schedule, request, performance를 조회할 수 있다.
  • 통합 메시지 실패를 재처리할 수 있다.
  • 과거 실적을 당시 모델 revision 기준으로 해석할 수 있다.
