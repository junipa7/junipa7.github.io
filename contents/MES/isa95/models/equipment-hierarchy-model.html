이 문서는 ANSI/ISA-95를 기반으로 MES/MOM 시스템 설계를 학습하기 위한 교육용 해설입니다. 공식 표준 조항을 대체하지 않으며, 실제 프로젝트에서는 최신 ISA-95 문서, 고객 URS, 사이트 표준, ERP/PLC/SCADA 연동 규격을 함께 검토해야 합니다.

1. 모델 목적

Enterprise, Site, Area, Work Center, Work Unit 같은 계층으로 생산 자원의 위치와 책임 범위를 표현합니다.

ISA-95 모델은 화면 이름을 정하는 용도가 아니라 시스템 사이의 데이터 계약을 정하는 기준입니다. 같은 설비, 자재, 작업 요청을 ERP, MES, SCADA가 서로 다르게 해석하면 통합 비용이 커지므로 객체의 경계와 관계를 먼저 맞춰야 합니다.

2. 핵심 구조

객체역할수업식 해설
Enterprise회사 또는 사업 단위여러 site를 포괄하는 최상위 조직입니다.
Site공장하나의 물리적 생산 사업장입니다.
Area생산 구역라인, 공정군, 창고 구역처럼 운영 단위를 나눕니다.
Work Center작업 센터스케줄과 capacity를 관리하는 단위입니다.
Work Unit작업 설비실제 작업이 수행되는 설비, 셀, 장치입니다.

3. 모델 DFD

단계의미모델링 포인트
1. Enterprise상위 개념 또는 입력 객체입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
2. Site관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
3. Area관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
4. Work Center관계, 계층, 상태 또는 능력을 해석하는 중간 모델입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.
5. Work Unit하위 시스템이나 통합 메시지가 사용하는 결과입니다.ID, parent 관계, revision, owner system, effective date를 관리합니다.

5. 설계 규칙

규칙 ID설계 규칙검증 방법
MR-01계층 ID는 ERP, MES, SCADA에서 공통으로 매핑되어야 합니다.모델 validation, master data governance, integration contract test로 검증
MR-02상위 계층 상태가 내려가면 하위 자원 가용성에도 영향을 줍니다.모델 validation, master data governance, integration contract test로 검증
MR-03Capacity 집계는 Work Unit에서 시작해 Work Center, Area로 올라갑니다.모델 validation, master data governance, integration contract test로 검증

모델 검증 의사코드

function validateIsa95Model(modelObject): assert modelObject.id is stable assert modelObject.ownerSystem is not empty assert modelObject.effectiveFrom is valid validateHierarchyOrRelationship(modelObject) validateExternalMappings(modelObject) publishModelChangedEvent(modelObject)

6. 통합 관점

ERP계획, 품목, 주문, 원가와 연결되는 상위 기준정보를 제공합니다.
MES/MOM실행 상태, schedule, performance, genealogy를 관리합니다.
SCADA/PLC실제 설비 상태와 공정 데이터를 이벤트로 제공합니다.

7. 테스트 시나리오

테스트 ID시나리오기대 결과
TC-01계층 tree 조회객체 관계, ID 매핑, revision, 통합 메시지가 설계와 일치해야 합니다.
TC-02Work Unit 상태 변경 후 Work Center capacity 재계산객체 관계, ID 매핑, revision, 통합 메시지가 설계와 일치해야 합니다.
TC-03site별 자원 필터객체 관계, ID 매핑, revision, 통합 메시지가 설계와 일치해야 합니다.
TC-04비활성 계층 사용 차단객체 관계, ID 매핑, revision, 통합 메시지가 설계와 일치해야 합니다.

8. 운영 체크리스트

  • 객체 ID와 외부 시스템 ID 매핑표가 있다.
  • 기준정보 owner system과 변경 승인 절차가 명확하다.
  • 모델 변경 시 영향받는 schedule, request, performance를 조회할 수 있다.
  • 통합 메시지 실패를 재처리할 수 있다.
  • 과거 실적을 당시 모델 revision 기준으로 해석할 수 있다.
