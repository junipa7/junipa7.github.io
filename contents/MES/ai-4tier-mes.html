AI 포함 4티어 MES 시스템 개발 보강 항목

핵심 결론

MESA-11 기능만으로는 MES의 업무 범위를 설명할 수 있지만, 실제 개발을 시작하려면 4티어 아키텍처, 데이터 표준, 설비 연동, AI/MLOps, 보안, 검증, 운영 체계가 함께 정의되어야 합니다. 아래 항목을 추가하면 “무엇을 만들 것인가”에서 “어떻게 안정적으로 운영할 것인가”까지 범위가 선명해집니다.

1. 4티어 구조 정의

티어 역할 주요 구성 개발 시 확인할 점
1티어: Presentation 작업자, 관리자, 엔지니어가 사용하는 화면 계층 작업 지시 화면, Andon, KPI 대시보드, 모바일/태블릿 UI, 관리자 콘솔 현장 화면은 클릭 수, 스캔 동선, 오류 복구 흐름까지 설계해야 합니다.
2티어: Application / Service MES 업무 규칙과 상태 전이를 처리하는 핵심 계층 Work Order, Dispatch, WIP, Quality, Maintenance, Traceability, Rule Engine Lot, 설비, 작업자, 자재의 상태 모델과 트랜잭션 경계를 명확히 해야 합니다.
3티어: Data / Integration 데이터 저장, 메시지 중계, 외부 시스템 연동 계층 RDB, Time-series DB, Event Broker, API Gateway, ETL/ELT, Data Lakehouse 현재 상태 테이블과 이력 테이블을 분리하고, 이벤트 시간과 수집 시간을 함께 관리해야 합니다.
4티어: Shopfloor / Edge 설비, 센서, PLC, EAP, SCADA와 연결되는 현장 계층 PLC, OPC UA, SECS/GEM, EAP, Edge Gateway, Barcode/RFID, Vision 장비 네트워크 단절, 중복 이벤트, 지연 수집, 설비 상태 불일치에 대한 복구 정책이 필요합니다.

2. AI 기능 추가 범위

AI는 MES를 대체하는 별도 시스템이 아니라, MES의 상태와 이력 데이터를 활용해 예측, 추천, 이상 감지, 최적화, 자연어 업무 지원을 제공하는 보조 판단 계층으로 설계하는 것이 안전합니다.

AI 영역 예시 기능 필요 데이터 주의점
예지 보전 고장 가능성 예측, PM 시점 추천, 이상 진동/전류 감지 설비 상태, 알람, 정비 이력, Run hour, 센서 시계열 AI 예측만으로 설비를 정지시키기보다 승인/검증 단계를 둡니다.
품질 예측 불량 가능성 예측, SPC 이상 신호 탐지, 검사 샘플링 추천 검사 결과, 공정 파라미터, Recipe, Lot 이력, 작업자/설비 조건 모델 입력값이 Lot/공정 문맥과 정확히 연결되어야 합니다.
스케줄 최적화 병목 예측, 우선순위 추천, Setup 최소화, 납기 리스크 알림 작업 계획, 설비 캘린더, 자재 가용성, WIP, Cycle time 추천 결과와 실제 작업자의 선택 결과를 함께 저장해야 개선이 가능합니다.
공정 이상 감지 비정상 Recipe, 센서 Drift, 반복 알람 패턴, 공정 조건 이탈 탐지 Raw data, Contextualized data, Alarm/Event, Recipe parameter 오탐을 줄이기 위해 Rule 기반 검증과 AI 판단을 함께 사용합니다.
업무 지식 지원 자연어 질의, SOP 검색, 장애 원인 후보 제시, 작업 로그 요약 SOP, 설비 매뉴얼, 변경 이력, 장애 조치 이력, 품질 보고서 권한별 문서 접근 제어와 답변 근거 표시가 필수입니다.

3. 추가해야 할 설계 산출물

  1. 도메인 모델 Work Order, Lot, Operation, Resource, Material, Person, Recipe, Inspection, Alarm의 상태와 관계를 정의합니다.
  2. 상태 전이표 Lot 상태, 설비 상태, 작업 지시 상태, Hold/Release, Rework, Scrap의 전이 조건과 권한을 문서화합니다.
  3. 인터페이스 명세 ERP, PLM, WMS, QMS, CMMS, EAP, SCADA, PLC, Barcode/RFID와 주고받는 메시지, 주기, 재처리 방식을 정의합니다.
  4. 데이터 품질 규칙 누락, 중복, 지연, 단위 불일치, 시간 동기화, 설비 ID 매핑 오류를 탐지하는 규칙을 둡니다.
  5. AI 모델 카드 모델 목적, 학습 데이터, 입력/출력, 성능 지표, 제한 사항, 재학습 조건, 승인자를 기록합니다.
  6. 운영 Runbook 장애 대응, 데이터 재처리, 인터페이스 중단, 모델 배포/롤백, 설비 연결 복구 절차를 정리합니다.

4. 데이터 아키텍처 보강

MES 데이터는 “현재 상태”와 “이력/이벤트”를 분리해야 합니다.

화면과 제어 판단은 현재 상태를 빠르게 읽어야 하고, 추적성/품질/AI는 이력 데이터를 길게 보관해야 합니다. 두 목적을 하나의 테이블로 처리하면 성능, 감사, AI 학습 품질이 모두 흔들릴 수 있습니다.

데이터 영역 권장 저장소 예시
업무 트랜잭션 RDBMS work_order, lot_current, dispatch_queue, quality_result, hold_release
이벤트 이력 RDBMS + Event Store execution_event, lot_history, resource_status_history, alarm_history
고주기 설비 데이터 Time-series DB 또는 Data Lake sensor_value, trace_data, process_parameter_stream
AI 학습/분석 데이터 Lakehouse / Feature Store feature_set, model_dataset, prediction_result, model_feedback
감사/보안 로그 Immutable Log 또는 SIEM 연계 user_action_log, approval_log, interface_access_log

5. AI/MLOps 운영 항목

  • Feature Store: 모델 입력 피처의 정의, 계산 방식, 버전, 기준 시간을 관리합니다.
  • Model Registry: 운영 모델, 후보 모델, 폐기 모델을 버전별로 관리합니다.
  • Inference API: MES 서비스가 AI 예측을 호출하는 표준 API를 제공합니다.
  • Human-in-the-loop: 추천 결과를 작업자나 엔지니어가 승인, 거절, 수정할 수 있게 합니다.
  • Monitoring: 예측 정확도, 데이터 드리프트, 응답 시간, 오탐/미탐, 모델 사용률을 감시합니다.
  • Rollback: 모델 성능 저하나 장애 발생 시 이전 모델 또는 Rule 기반 처리로 돌아갈 수 있어야 합니다.

6. 보안과 권한

영역 추가 내용
사용자 권한 역할 기반 권한(RBAC), 공정/라인별 데이터 접근 권한, 승인 권한 분리
설비/Edge 보안 장비 계정 관리, 인증서, 네트워크 분리, 원격 접속 통제, 변경 로그
AI 보안 학습 데이터 접근 제어, 모델 파일 무결성, 프롬프트/문서 접근 권한, 민감 정보 마스킹
감사 추적 작업 변경, 품질 판정, Hold 해제, Recipe 변경, AI 추천 승인/거절 이력 보관

7. 테스트와 검증

정상 케이스보다 예외 케이스가 중요합니다.

MES는 현장 장애, 지연 이벤트, 설비 통신 중단, 기준정보 불일치 상황에서도 생산 이력을 잃지 않아야 합니다. AI 기능도 모델 정확도뿐 아니라 “잘 모를 때 어떻게 멈추고 사람에게 넘길 것인가”를 검증해야 합니다.

  1. 설비 이벤트 중복 수신, 지연 수신, 순서 역전 테스트
  2. ERP 계획 변경 중 작업 착수/완료가 동시에 발생하는 테스트
  3. Lot Hold 상태에서 Dispatch, 검사, 출하가 차단되는지 확인
  4. Recipe 또는 작업표준 개정 시점과 Lot 적용 기준 검증
  5. AI 예측 결과가 권한 없는 사용자에게 노출되지 않는지 확인
  6. AI 모델 장애 시 Rule 기반 대체 처리 또는 수동 처리로 전환되는지 확인
  7. 데이터 재처리 후 현재 상태와 이력 데이터가 일관되는지 검증

8. 단계별 개발 로드맵

단계 목표 주요 산출물
1단계: Core MES 작업 지시, Dispatch, WIP, 실적, 품질 기본 기능 구현 도메인 모델, 상태 전이표, 핵심 화면, RDB 스키마
2단계: Shopfloor Integration 설비/EAP/PLC/Barcode/RFID 연동과 이벤트 기반 수집 구현 인터페이스 명세, Edge Gateway, 이벤트 재처리 정책
3단계: Analytics OEE, 품질, 병목, 생산성 분석 데이터 마트 구축 KPI 정의서, 이력 테이블, 대시보드, 데이터 품질 규칙
4단계: AI Pilot 예지 보전, 품질 예측, 이상 감지 중 ROI가 높은 1~2개 기능 파일럿 Feature Store, 모델 카드, Inference API, 검증 리포트
5단계: AI Operations AI 모델 모니터링, 재학습, 승인/롤백 체계 운영화 MLOps 파이프라인, 모니터링 대시보드, 운영 Runbook

  • 4티어별 책임과 시스템 경계가 분리되어 있는가?
  • Lot, 설비, 자재, 작업자, Recipe의 상태 전이가 문서화되어 있는가?
  • 설비 데이터가 Lot/Operation/Resource 문맥과 연결되는가?
  • 현재 상태, 이력, 고주기 데이터, AI 학습 데이터를 분리해 저장하는가?
  • AI 추천 결과의 근거, 승인자, 적용 결과가 이력으로 남는가?
  • 모델 장애나 데이터 품질 저하 시 운영자가 알 수 있고 롤백할 수 있는가?
  • 보안, 감사, 권한, 변경 관리가 개발 초기부터 포함되어 있는가?
