[대용량 Data에서 Real ST를 산출방법]
(Chan알고리즘과 KLL 스케치)
	Convex Hull (볼록 껍질)
	정의
	2차원 또는 다차원 공간에 흩어져 있는 여러 점들을 모두 감싸는 **가장 작은 볼록한 다각형(또는 다면체)**을 의미합니다. 전산 기하학(Computational Geometry)에서 가장 기본적이면서도 중요한 개념입니다.
	가장 직관적인 비유는 **'고무줄 비유(Rubber Band Analogy)'**입니다. 널빤지 위에 여러 개의 못(데이터 점)이 박혀 있다고 상상해 보세요. 커다란 고무줄을 팽팽하게 늘려서 모든 못을 바깥쪽에서 감싸도록 놓았을 때, 고무줄이 수축하면서 바깥쪽 못들에 걸쳐 만들어지는 형태가 바로 이 못들의 Convex Hull입니다.
 
	두개의 Convex Hull의 병합
빨간 선의 점들이 병합된 Data입니다.
 
	기하학적 및 수학적 정의
	볼록(Convex)의 의미: 다각형 내부에 있는 임의의 두 점을 골라 선분으로 연결했을 때, 그 선분이 다각형의 경계선 밖으로 전혀 나가지 않는 형태를 말합니다. 반대로, 별 모양처럼 선분이 밖으로 나가는 구간이 생기면 '오목(Concave)'하다고 합니다.
	최소성(Minimality): 점 집합 S를 포함하는 볼록 다각형은 무수히 많을 수 있지만, Convex Hull은 그 중에서 '가장 작은(면적이 최소인)' 다각형입니다.
	정점(Vertex): Convex Hull의 꼭짓점을 이루는 점들을 '극단점(Extreme Points)'이라고 하며, 이들은 원래 점 집합 S에 속해 있는 데이터들 중 가장 외곽에 위치한 데이터들입니다.
	주요 탐색 알고리즘 요약
아래 알고리즘들이 바로 이 Convex Hull을 얼마나 빠르고 효율적으로 찾느냐를 해결하기 위한 방법론들입니다
	Jarvis March (선물 포장 알고리즘, Gift Wrapping):
	가장 왼쪽의 점에서 시작하여 각도가 가장 큰 반시계 방향의 다음 점으로 이동을 반복면서 선물을 포장하듯 다음 점을 각도로 찾아 나갑니다.
	시간 복잡도: O(nh) (n: 전체 점 개수, h: 껍질 정점 개수)
 
 
	Graham Scan (그레이엄 스캔):
	각도를 기준으로 모든 점을 한 번 정렬(O(n log⁡〖n)〗)한 뒤, 스택(Stack)을 이용해 한 바퀴를 돌며 단번에 껍질을 완성합니다.
 
	완성된 껍질에서 오목(Concave)점을 제거합니다.
 
	Chan's Algorithm (찬의 알고리즘):
	데이터를 그룹으로 나누어 Graham Scan을 수행한 뒤, Jarvis March 방식을 응용해 병합함으로써 O(n log⁡〖h)〗라는 이론적 최적의 속도를 달성합니다.
 
	Real ST산출을 위한 Chan알고리즘과 KLL 스케치
	개요
데이터 분석 및 통계 처리 분야에서 대규모 데이터 집합(Data Stream)의 특성을 효율적으로 파악하기 위해 사용되는 Chan Algorithm과 KLL Sketch에 대해 정리합니다.
	Chan Algorithm (주로 기하학적 통계 및 최적화)
일반적으로 통계 및 전산 기하학에서 언급되는 Chan's Algorithm은 평면상의 점 집합에서 **Convex Hull(볼록 껍질)**을 찾는 가장 효율적인 알고리즘 중 하나입니다. 대규모 데이터의 외곽 경계(Outlier 감지나 데이터 분포 범위 확인)를 계산할 때 필수적입니다. 데이터 세트의 범위(Range) 파악, 클러스터링의 경계 분석, 다변량 데이터의 분포 시각화 기초 자료에 사용됩니다.
	KLL (Karnin-Lang-Liberty) Sketch
KLL 알고리즘은 스트리밍 데이터에서 **Quantiles(분위수)**를 추정하기 위해 설계된 최신 알고리즘입니다. Apache DataSketches 라이브러리 등에 포함되어 실무에서 널리 쓰입니다.
수억 개의 데이터가 실시간으로 들어올 때, 모든 데이터를 정렬하여 "상위 1% 값"이나 "중간값(Median)"을 찾는 것은 메모리상 불가능합니다. KLL은 아주 적은 메모리만 사용하면서도 매우 높은 정확도로 이 값들을 추정합니다.
	요약 및 비교
Compaction은 KLL Sketch 알고리즘의 핵심 단계이며, Chan's Algorithm은 기하학적 데이터의 외곽 경계(Convex Hull)를 찾는 알고리즘입니다.
구분	Chan Algorithm	KLL Sketch
주요 목적	데이터의 기하학적 경계(Convex Hull) 계산	데이터의 분포(분위수, 중앙값) 추정
적용 분야	패턴 인식, 충돌 감지, 외곽점 분석	로그 분석, 대규모 트래픽 모니터링, 성능 지표(P99) 계산
강점	이론적 최적 속도 (O(n log⁡h ))	고정된 메모리로 실시간 스트림 처리 가능
	설계 중인 시스템에서 **"특정 Cycle Time의 하위 5% 값을 찾는 것"**이 목적이라면 KLL이 적합하고, **"가동 시간과 전력 소모량 사이의 유효 범위를 정의하는 것"**이 목적이라면 Chan이 더 적합합니다.
	Chan's Algorithm
Real ST산출을 위한 분석을 위해 "데이터의 외곽 경계(범위)를 파악"하고자 하시는 맥락에서, Chan's Algorithm의 상세 작동 단계를 정리합니다.
 평면 상의 n개의 점으로부터 **Convex Hull(볼록 껍질)**을 찾는 알고리즘으로, Graham Scan의 정교함과 Jarvis March의 효율성을 결합한 형태입니다. 이 알고리즘의 핵심은 **"적절한 그룹 크기(m)를 미리 가정하고 처리한다"**는 점에 있습니다.
 
	Chan's Algorithm 상세 작동 단계
이 알고리즘은 전체 점의 개수가 n, 최종 볼록 껍질의 정점 개수가 h일 때, 이론적 최적치인 O(n log⁡〖h)〗 복잡도를 달성합니다.
	그룹 분할 (Partitioning)
전체 점 집합 P를 크기가 m인 r개의 그룹으로 나눕니다.
	그룹의 수: r=⌈n/m⌉
	수식: P={P_1, P_2,..., P_r,} 이며, 각 |P_i |≤m 입니다.
	개별 Convex Hull 생성 (Graham Scan)
각 그룹 P_i에 대해 Graham Scan 알고리즘을 적용하여 각각의 작은 볼록 껍질 〖CH〗_i를 구합니다.
	시간 복잡도: 각 그룹당 O(m log m)이 소요되므로 전체적으로는 다음과 같습니다.
O(n/m∙m log⁡m )  =O(n log⁡〖m)〗
	Jarvis March를 이용한 병합 (Gift Wrapping)
가장 왼쪽에 있는 점 P_i에서 시작하여, 전체 껍질의 다음 정점 Pk+1을 찾습니다. 이때 각 그룹의 껍질(〖CH〗_i)과 현재 점(P_k) 사이의 **접선(Tangent)**을 이진 탐색으로 찾습니다.
	접점 탐색: P_k에서 각 〖CH〗_i로의 접선을 찾는 시간은 O(log⁡〖m)〗입니다.
	다음 정점 결정: r개의 그룹 중에서 가장 외곽에 있는 점을 고르는 과정은 O(r log⁡〖m)〗입니다.
	전체 병합 복잡도: 이 과정을 h번 반복하므로 최종 병합 시간은 다음과 같습니다.
O(h∙n/m  log⁡m )
	반복적 파라미터 최적화 (Iterative Strategy)
우리는 h를 미리 알 수 없으므로, m을 2^(2^t ) (t=1,2,…)순으로 기하급수적으로 키우며 위 과정을 반복합니다.
	최종 시간 복잡도 합계:
∑_(t=1)^log⁡log⁡h ▒〖n∙log⁡(2^(2^t ))=∑_(t=1)^log⁡log⁡h ▒〖n∙2^t 〗〗=O(n log⁡〖h)〗
	Real ST 적용 시나리오
	설비 파라미터 경계면(Envelope) 분석:
성능 효율을 계산할 때, 단순히 평균값을 쓰는 대신 Chan's Algorithm을 사용하여 **'정상 가동 범위(Normal Operating Zone)'**의 기하학적 경계를 확정할 수 있습니다. 경계 밖의 데이터는 정지유실인 'Loss'나 'Down' 상태와 연관된 이상치로 분류합니다.
	분산 데이터 요약:
여러 대의 설비(r개)에서 각각 계산된 〖CH〗_i 정보만 중앙 서버로 보내면, 서버는 전체 원시 데이터를 볼 필요 없이 접선 계산(O(n log⁡〖m)〗)만으로 라인 전체의 성능 분포 경계를 즉시 합성할 수 있습니다.
	KLL(Karnin-Lang-Liberty) Sketch
대규모 스트리밍 데이터에서 분위수(Quantile)를 추정하는 강력한 도구입니다.
특히 설비의 '성능 효율(Performance Efficiency)'을 계산할 때 발생하는 이상치(Outlier) 제거 및 정확한 백분위수(P90, P99 등) 파악을 위해 KLL의 Compaction(압축) 과정이 핵심적인 역할을 합니다.
 
	KLL 알고리즘의 구조: 계층적 버퍼 (Hierarchical Buffers)
KLL은 여러 개의 **Level(H)**로 구성된 버퍼 구조를 가집니다. 각 레벨 i는 용량 k_i를 가지며, 레벨이 올라갈수록 데이터의 '가중치'는 2배씩 증가합니다.
	Level 0: 원래의 데이터(가중치 1)가 들어오는 곳입니다.
	Level i: 가중치가 2^i인 데이터들이 저장됩니다.
	상세 작동 단계: Compaction 과정
Compaction은 특정 레벨의 버퍼가 가득 찼을 때, 데이터를 상위 레벨로 보내면서 크기를 줄이는 핵심 프로세스입니다.
	트리거 (Trigger)
레벨 i의 데이터 개수가 미리 정의된 용량 k_i를 초과하면 압축이 시작됩니다.
	정렬 (Sorting)
해당 레벨의 버퍼에 있는 데이터들을 오름차순으로 정렬합니다.
X={x_1,x_2,…,x_n }  (x_1≤x_2≤⋯≤x_n )
	선택 및 제거 (Selection & Eviction)
정렬된 데이터 중 홀수 번째 또는 짝수 번째 데이터만 선택하여 상위 레벨(i+1)로 보냅니다. 이때 선택은 무작위(Random)로 결정하여 편향(Bias)을 방지합니다.
	**동전 던지기(b∈{0,1})**를 통해 결정:
	b=0이면: {x_2,x_4,x_6,…} 를 상위 레벨로 전달
	b=1이면: {x_1,x_3,x_(5,)…} 를 상위 레벨로 전달
	선택되지 않은 나머지 절반의 데이터는 메모리에서 완전히 삭제됩니다.
	가중치 갱신 (Weight Update)
상위 레벨로 올라간 데이터는 이제 이전보다 2배의 가중치를 갖게 됩니다.
	Level i의 데이터 2개가 Level i+1의 데이터 1개로 대체되지만, 가중치가 2^i에서2^(i+1)로 변하므로 전체 통계적 분포(Sum of Weights)는 유지됩니다.
	수식적 이해와 오차 보장
KLL 알고리즘의 가장 큰 장점은 메모리 사용량과 오차 범위 사이의 관계를 수학적으로 증명했다는 점입니다.
	레벨별 용량 설정 (k_i)
메모리를 효율적으로 쓰기 위해 상위 레벨로 갈수록 버퍼 크기를 기하급수적으로 줄입니다.
k_i≈k∙c^(H-i)
          (여기서 k는 전체 파라미터, c는 1보다 작은 상수(약 2/3)입니다.)
	오차 범위 (ϵ)
사용자가 허용하는 오차 ϵ에 대해, KLL Sketch가 필요한 메모리 공간 M은 다음과 같습니다.
M=O(1/ϵ  log⁡〖log 1/ϵ〗 )
	이는 기존의 다른 알고리즘(예: GK Array)보다 훨씬 적은 메모리로도 동일한 정확도를 낼 수 있음을 의미합니다.
	설비종합효율 표준 데이터 분석에의 응용
	실시간 OEE 모니터링: 설비에서 발생하는 수백만 건의 Event나 처리 시간 데이터를 DB에 다 쌓지 않고도, 메모리 내에서 즉시 95% 신뢰 구간의 성능 지표를 산출할 수 있습니다.
	이상치(Outlier) 필터링: 성능 효율을 계산할 때, 비정상적으로 길게 측정된 Cycle Time을 KLL의 분위수 기반 필터링(예: 상위 99.9% 제외)을 통해 자동 제거하여 데이터의 정밀도를 높일 수 있습니다.
	분산 데이터 통합: 여러 대의 설비(Equipment)에서 각각 생성된 KLL Sketch를 중앙 서버로 보내기만 하면, 추가 연산 없이 '병합(Merge)'하여 라인 전체의 통합 통계 데이터를 얻을 수 있습니다.
	성능 지표 산출 로직을 설계
설비상태 및 효율에 기반하여 대규모 설비 데이터 스트림을 처리하기 위해, **Chan's Algorithm(기하학적 경계 산출)**과 **KLL Sketch(통계적 분포 추정)**를 결합한 통합 이상치 제거 및 성능 지표 산출 로직을 설계합니다.
이 통합 로직은 다차원 데이터의 경계(Hull)와 단일 변수의 분포(Quantile)를 모두 고려하여 정교하게 이상치를 필터링하고, 최종적으로 정확한 성능 효율(Performance Efficiency)을 계산하는 데 초점을 맞춥니다.
	통합 분석 로직 개요 (Integrated Logic Overview)
이 로직은 데이터 수집부터 최종 지표 산출까지 4단계로 구성됩니다.
	주요 구성 요소 및 역할
	RUN Filter: 설비 상태가 'PRD(Production)'인 유효 가동 시간 데이터만 추출합니다.
	Chan's Algorithm Engine: 다차원 파라미터(예: 온도 vs 압력)의 기하학적 정상 가동 범위(Operating Envelope)를 계산합니다.
	KLL Sketch Engine: 단일 성능 지표(예: Standard Time)의 실시간 백분위수(P99, Median)를 추정합니다.
	Anomaly Detection & KPIs: 두 알고리즘의 결과를 결합하여 이상치를 제거하고 설비종합효율을 산출합니다.
	상세 통합 단계 (Detailed Step-by-Step Logic)
	Step 1: 데이터 수집 및 설비 상태 분류 (Data Ingestion & State Classification)
설비에서 발생하는 실시간 이벤트 및 센서 데이터를 수집하고 상태를 분류합니다.
	Input: 실시간 데이터 스트림 S={(t,State,v_1,v_2,⋯,v_k,CT)}
	t: 타임스탬프, v_i : 센서값, CT : Cycle Time
	Action: State == 'PRD'인 데이터만 필터링하여 분석 데이터 세트 D를 구성합니다.
	Step 2: 다차원 및 단일 변수 특징 추출 (Feature Extraction)
필터링 된 데이터 D에 대해 두 알고리즘을 병렬로 적용하여 데이터의 '모양'과 '분포'를 파악합니다.
	Chan's Algorithm (다차원 경계 산출)
주요 공정 파라미터(예: v_1: 온도, v_1: 압력)를 좌표 평면에 매핑하고 볼록 껍질(Convex Hull)을 계산합니다.
	Input: 점 집합 P={(v_1,v_2 )_j  ϵ D}
	Action: P를 크기 m의 그룹으로 나누고 Graham Scan 후 Jarvis March로 병합하여 최종 Hull H를 산출합니다.
	Output: 정상 가동 범위의 정점 집합 H={p_1,p_2,⋯,p_h }
	KLL Sketch (단일 변수 분포 추정)
성능 효율의 핵심 지표인 Cycle Time(CT)에 대해 KLL Sketch를 생성하고 업데이트합니다.
	Input: CT 값 스트림 〖CT〗_stream={〖CT〗_j  ϵ D}
	Action: 계층적 버퍼와 무작위 Compaction을 통해 메모리 효율적인 Sketch K를 유지합니다.
	Output: P99(이상치 임계값) 및 Median(실제 속도) 추정값 Q={q ̂_0.99,q ̂_0.50 }
	Step 3: 이중 구조 이상치 제거 (Two-tier Outlier Removal)
신규 데이터 x에 대해 기하학적 경계(Chan)와 통계적 임계값(KLL)을 모두 적용하여 이상치 여부를 판별합니다.
	판별 로직:
	기하학적 검사 (Chan): x의 공정 파라미터 v_1,v_2가 Hull H의 내부에 존재하는지 확인합니다. (외적 이용)
	통계적 검사 (KLL): x의 CT 값이 P99 임계값 q ̂_0.99보다 작은지 확인합니다.
	결과: 두 조건을 모두 만족하는 데이터만 **'정상 데이터 D_clean'**으로 분류하고, 나머지는 중지유실의 'Loss' 또는 'Down' 상태와 연관된 이상치로 마킹하여 제외합니다.
D_clean={x ϵ D | (isInside(H,x∙v))∧(x.CT< q ̂_0.99)}
	Step 4: 설비종합효율 성능 지표 산출 (Performance KPI Calculation)
정상 데이터 D_clean만을 사용하여 설비종합효율 표준에 기반한 정확한 성능 효율을 계산합니다.
	이론적 속도: 설비 설계 사양에 따른 Theoretical Cycle Time (TCT)
	실제 속도: 정상 데이터 D_clean에서 KLL Sketch가 추정한 **Median CT (q ̂_0.50)** 사용
	성능 효율 (y) 계산:
 y=(TCT/q ̂_0.50 )×100(%)
	통합 로직의 장점 및 활용
	정밀한 이상치 제거: 단일 변수(CT)만 고려했을 때 놓칠 수 있는 공정 파라미터의 이상 징후를 Chan's Algorithm의 다차원 경계 분석으로 잡아낼 수 있습니다.
	실시간성 및 낮은 오버헤드: 두 알고리즘 모두 대용량 데이터를 메모리에 다 쌓지 않고 요약본(Sketch, Hull Points)만 유지하므로 실시간 OEE 모니터링 시스템에 적합합니다.
	설비 상태 분류 및 설비종합효율 산식을 수학적 근거를 가진 알고리즘과 결합하여 표준의 정확도를 높입니다.
 
	KLL & Chan 기반 설비 효율 분석 시스템 아키텍처
현장의 설비부터 최종 관리자의 대시보드(MES)까지 데이터가 흘러가는 전체 시스템 구성도.
 
 
	데이터 수집 계층 (Edge Network)
	설비 (Equipment): 반도체나 디스플레이 공정 설비입니다.
	Edge Gateway (SECS/GEM 통신): 설비에서 올라오는 원시 데이터를 1차적으로 수집합니다. 여기서는 SEMI 표준이 정의하는 Product Time을 기준으로 순수하게 제품 생산에 소요되는 Cycle Time과, 온도/압력 등의 센서 데이터를 파싱하여 상위 서버로 전송합니다.
	실시간 분석 계층 (Stream Processor)
안정적인 서버 환경에서 실시간 스트림 처리 엔진이 구동됩니다.
	Chan Engine (기하학적 경계 산출): 공정 변수(온도, 압력 등)를 다차원으로 분석하여 정상 가동 범위(Convex Hull)를 실시간으로 학습하고 업데이트합니다.
	KLL Engine (통계적 분포 추정): 수많은 Cycle Time 데이터를 메모리상에서 압축(Compaction)하여, P99(이상치 임계값)와 중위수(실제 생산 속도)를 계산합니다.
	통합 필터 (Outlier Filter): 두 엔진의 결과를 종합하여, 장비의 스파이크성 에러나 통신 오류로 인한 가짜 데이터를 걸러냅니다.
	데이터 저장 계층 (Database)
	Oracle / MSSQL (MES DB): 정제된 성능 지표, 상태 로그(E10), 그리고 최종 계산된 설비별/라인별 OEE 데이터를 안정적으로 저장하는 관계형 데이터베이스입니다. Chan 알고리즘에서 도출된 정상 가동 범위의 기준 좌표들이나, KLL Sketch의 압축된 요약본(Metadata)도 이 DB에 저장되어 이력 관리에 사용됩니다.
	애플리케이션 및 시각화 계층 (Application)
OEE Calculator (효율 계산기): 앞서 KLL 엔진에서 추출된 '정제된 실제 속도'와 SEMI Product Time 기반의 '표준 시간(Standard Time)'을 비교합니다.
	이 모듈은 양품율(Quality)을 제외하고, 시간가동율(Availability)과 성능가동율(Performance Efficiency)의 곱만으로 OEE를 산출하도록 엄격하게 세팅 됩니다.
OEE = Availability × Performance
	Dashboard: 도출된 최종 지표를 시각화하여 운영자에게 제공합니다.

	Data Flow Diagram[Level 1] - Chan & KLL 결합형 설비 효율 분석 시스템
이 설계는 실시간으로 유입되는 대량의 설비 데이터를 '기하학적 경계(Chan)'와 '통계적 분포(KLL)'라는 두 가지 필터를 통해 정제하는 흐름에 집중합니다.
	데이터 흐름 구성 요소
 
구분	명칭	설명
External Entity	Equipment (설비)	PLC/GEM을 통해 상태(E10), 공정 변수(온도/압력), Cycle Time 데이터 송신
Process 1.0	E10 State Filter	설비 상태를 분석하여 'Production(PRD)' 상태의 유효 데이터만 통과
Process 2.0	Boundary & Dist. Engine	Chan으로 가동 범위(Hull) 계산, KLL로 분위수(Quantile) 추정

Process 4.0	E79 Efficiency Calc	정제된 데이터의 Median 값을 활용하여 성능 효율(y)산출

	상세 데이터 흐름 (Data Flow Details)
	Raw Sensor Stream: 설비로부터 수집된 Raw 데이터 (State, Temp, Press, Cycle Time).
	Valid Production Data: E10 기준 '실제 가동 중'인 데이터 세트.
	Hull Vertices (P_1,⋯,P_h): Chan 알고리즘으로 추출된 정상 가동 범위의 외곽 점들.
	Estimated Quantiles (q ̂_0.50,q ̂_0.99): KLL로 추정된 중위수 및 이상치 임계값.
	Refined Performance Data: 이중 필터를 통과한 순수 성능 데이터.
	OEE/Performance Metrics: SEMI E79 표준에 부합하는 최종 효율 지표.
	핵심 로직의 흐름 (Process 3.0 내부)
Process 3.0(통합 필터)에서는 다음과 같은 조건문을 통해 데이터 정제(D_clean)가 이루어집니다.
	조건 A (Chan): 신규 데이터의 공정 변수 v가 Hull H 내부에 있는가?
	판정식: ∀_e  ∈Edges(H),CrossProduct(e,v)≥0
	조건 B (KLL): 신규 데이터의 Cycle Time CT가 임계값보다 작은가?
	판정식: CT<q ̂_0.99
	결과: (조건 A AND 조건 B)를 만족하는 데이터만 최종 통계 계산에 사용됨으로써, 장비의 일시적 튀는 현상(Spike)이나 센서 오작동으로 인한 성능 지표 왜곡을 원천 차단합니다.
 
	Data Flow Diagram[Level 2] - [Process 1.0] E10 State Filter
이 프로세스는 설비에서 올라오는 무수한 원시 데이터 중, 향후 생산성 계산의 절대적 기준이 되는 **'표준시간(Standard Time)'**을 도출하기 위해 SEMI에서 정의하는 Product Time을 정확히 발라내는 핵심 역할을 수행합니다.
	 
	1.1 Raw Event Parsing (원시 이벤트 파싱)
	입력: 설비 통신(SECS/GEM)을 통해 들어오는 실시간 원시 로그 (알람, 상태 변경 이벤트, 온도/압력 센서 값 등).
	작업: 비정형 메시지를 시스템이 인식할 수 있는 구조화된 포맷으로 변환합니다.
	출력: Timestamp, Event ID, 공정 파라미터 배열
	1.2 E10 State Classification (E10 상태 분류)
	작업: 추출된 Event ID와 설비의 현재 신호를 기반으로, SEMI E10 표준이 정의하는 6대 기본 상태(PRD, SBY, ENGR, SDT, USD, NST) 중 하나로 맵핑합니다.
	핵심 로직: 설비가 실제로 제품을 생산 중인 상태(Production)인지, 대기 중(Standby)인지 명확하게 구분표를 작성하여 상태를 할당합니다.
	1.3 Product Time & Duration Calc (생산 시간 및 구간 계산)
	작업: 이전 상태와 현재 상태의 Timestamp 차이를 계산하여 해당 상태의 체류 시간(Duration)을 구합니다.
Duration= t_current-t_previous
	핵심 로직 (표준시간 기준 확립): 이 단계에서 산출되는 Product Time(PRD 상태 중 실제로 제품 가공에 소요된 시간)은 이후 KLL 및 Chan 알고리즘을 거쳐 성능가동율을 산출할 때 기준이 되는 '표준시간(Standard Time)'의 원천 데이터가 됩니다. 작업자나 설비의 숙련도 개념이 배제된, 순수하게 장비가 제품을 처리하는 데 쓴 절대적인 시간을 측정합니다.
	1.4 Data Segregation & Routing (데이터 분리 및 라우팅)
	작업: 계산된 데이터의 목적지를 분류합니다.
	출력 A (State DB 저장): 발생한 모든 상태 이력과 시간 정보는 관계형 DB(Oracle/MSSQL)에 저장되어, 나중에 OEE의 **시간가동율(Availability)**을 계산하는 데 사용됩니다.
	출력 B (알고리즘 엔진 전송): 상태가 'PRD(Production)'로 분류되고 정상적인 Product Time을 가진 데이터(공정 변수, Cycle Time)만 골라내어 다음 단계인 **Process 2.0 (Chan & KLL Engine)**으로 넘겨줍니다.
 
	Data Flow Diagram[Level 2] - [Process 2.0] Feature Extraction Engine
스트림 환경(예: 앞서 구성도에 있던 EES 서버)에서 대량의 데이터를 메모리 효율적으로 압축하고, 다차원 및 단일 차원의 특징(Feature)을 추출하는 핵심 연산 구간입니다.
Process 2.0 내부로 들어온 데이터는 특징(Feature)에 맞게 분리되어 각 알고리즘 엔진에서 처리됩니다.
 
	2.1 Data Router & Splitter (데이터 라우팅 및 분리)
	작업: Process 1.0에서 전달받은 정상 가동(PRD) 상태의 데이터를 분석 목적에 맞게 두 갈래로 나눕니다.
	출력 A: 온도, 압력 등 설비 파라미터로 구성된 다차원 벡터 데이터 (v_1,v_2,⋯)는 Chan Algorithm으로 보냅니다.
	출력 B: 설비의 생산 속도를 나타내는 절대적 기준 시간인 Cycle Time(CT) 데이터는 KLL Sketch로 보냅니다.
	2.2 Chan Algorithm Engine (기하학적 경계 모델링)
	작업: 다차원 공정 파라미터 좌표 평면에서 데이터의 외곽 경계를 감싸는 볼록 껍질(Convex Hull)을 실시간으로 업데이트합니다.
	핵심 로직:데이터를 m 크기의 그룹으로 분할하여 부분 껍질 계산 (O(n log⁡〖m)〗).Jarvis March 방식을 이용해 각 부분 껍질에 접선을 그어 전체 외곽 정점 확정 (O(h∙n/m  log⁡m).
	출력: 정상 가동 범위의 형태를 정의하는 정점 좌표들의 집합 H={p_1,p_2,⋯,p_n}
	2.3 KLL Sketch Engine (통계적 분포 모델링)
	작업: 수많은 Cycle Time(CT) 데이터를 계층적 버퍼에 담고 압축(Compaction)하여 메모리를 최적화하면서 전체 분포를 추정합니다.
	핵심 로직: 특정 버퍼 레벨이 꽉 차면 정렬 후 절반을 무작위로 삭제하고, 살아남은 데이터의 가중치를 2배(2^i→2^(i+1))로 올려 상위 레벨로 올립니다.
	출력: 이상치 컷오프 기준이 되는 P99 임계값(q ̂_0.99)과, 성능가동율 계산의 분모가 될 실제 중위 속도(q ̂_0.50)를 포함한 추정치 집합 Q
	2.4 Metadata Synchronization (메타데이터 동기화 및 출력)
	작업: 두 엔진에서 비동기적으로 계산된 기하학적 경계(H)와 통계적 임계값(Q)을 하나의 메타데이터 패키지로 묶어 동기화합니다.
	출력 A: 메모리 장애 대비 및 이력 추적을 위해 최신 요약본을 Redis나 MES 연동 DB(Oracle/MSSQL)에 직렬화하여 주기적으로 저장합니다.
	출력 B: 이어지는 Process 3.0(통합 이상치 필터)이 실시간으로 새 데이터를 검사할 수 있도록 기준점(Thresholds)을 즉시 제공합니다.
	Data Flow Diagram[Level 2] - [Process 3.0] Integrated Outlier Filter
 
	통합 필터링 판별식 (Filtering Logic)Process 3.0의 핵심은 신규 데이터 x가 입력되었을 때, 두 가지 독립적인 알고리즘의 결과를 AND 논리 게이트로 결합하여 평가하는 것입니다. 신규 데이터 객체 x는 다음과 같은 속성을 가집니다.
	x.v: 다차원 공정 파라미터 좌표 (예: 온도, 압력)
	x.CT: SEMI Product Time 기반의 Cycle Time
	3.1 조건 A: Chan Algorithm 기반 기하학적 타당성
입력된 공정 파라미터 x.v가 학습된 정상 가동 범위(Convex Hull, H) 내부에 안전하게 위치하는지 검사합니다.
	수학적 판별: 다각형의 각 변(Edge)과 점 x.v 사이의 **외적(Cross Product)**을 계산하여 방향성을 확인합니다. 모든 변에 대해 점이 같은 방향(예: 항상 좌측)에 있다면 내부에 있는 것으로 판정합니다.
Condition A=∀_e∈Edges(H),CrossProduct(e,x.v)≥0
	3.2조건 B: KLL Sketch 기반 통계적 타당성
입력된 생산 속도 x.CT가 KLL 엔진이 실시간으로 추정한 상위 1% 극단값(P99)을 초과하지 않는지 검사합니다. 이는 일시적인 지연이나 설비 잼(Jam) 현상으로 인해 길어진 CT를 성능 산출에서 배제하기 위함입니다.
	수학적 판별:
Condition B=x.CT< q ̂_(0.99)
	3.3 & 3.4교집합 판별 및 분류
두 조건을 모두 만족해야만 순수한 생산 데이터(D_clean)로 인정받아 다음 단계로 넘어갑니다.
	AND 연산식:
x∈D_clean⟺(Condition A)∧(Condition B)
	이상치 처리 로직:
만약 결과가 False라면, 어떤 조건에서 실패했는지에 따라 **원인 코드(Reason Code)**를 부여하여 Outlier Log DB에 저장합니다.
	A만 실패: 공정 조건 이탈 (Process Parameter Drift)
	B만 실패: 일시적 속도 저하 (Micro-stoppage / Performance Loss)
	A, B 동시 실패: 설비 심각한 이상 징후 (Critical System Error)

생산성 계산의 절대적 기준이 되는 **'표준시간(Standard Time)'**의 개념을 명확히 하고, 양품율을 배제한 OEE 산출 공식을 적용하여 설비 본연의 기계적 효율을 도출하는 데 집중합니다.
 
	4.1시간가동율 산출 (Availability Calculation)
	작업: Process 1.0에서 DB에 적재한 상태 로그(State Log)를 기반으로 설비가 실제 가동된 시간의 비율을 계산합니다.
	산식:
시간가동율=(실제 가동 시간(Uptime))/(총 부하 시간(Total Time))×100
	4.2 성능가동율 산출 (Performance Efficiency Calculation)
	작업: 정제된 KLL Sketch 데이터를 활용하여 설비가 설계된 속도 대비 얼마나 제 성능을 발휘했는지 측정합니다.
	핵심 기준 (Standard Time): 여기서 사용되는 **표준시간(Standard Time)**은 작업자나 설비의 정상적인 숙련도를 기준으로 하는 과거의 일반적인 개념을 철저히 배제합니다. 오직 SEMI에서 정의하는 Product Time을 기준으로 하여 생산성 계산의 절대적인 척도로 삼습니다.
	산식: 이상치가 제거된 KLL 추정 중위수(q ̂_0.50)를 실제 속도로 간주하여, 표준시간과의 비율을 구합니다.
성능가동율=(Product Time 기반 표준시간(Standard Time))/(KILL추정 중위 속도(Median CT))×100
	4.3종합설비효율 산출 (OEE Integration)
	작업: 앞서 도출된 두 가지 지표를 통합하여 설비의 최종 효율을 계산합니다.
	핵심 로직: 공정의 수율이나 불량률과 같은 요소는 설비 고유의 성능 지표에 왜곡을 줄 수 있으므로, 양품율(Quality Rate)은 평가에서 완전히 제외합니다. 오직 시간가동율과 성능가동율의 곱만으로 설비를 관리합니다.
	최종 산식:
OEE = 시간가동율 × 성능가동율
