KLL Quantile Sketch

대규모 스트리밍 데이터에서 전체 데이터를 보관하지 않고, 아주 적은 고정 메모리만을 사용하여 분위수(Quantiles, p50, p99 등)를 고정 오차 범위 내로 추정하는 압축 Sketch 알고리즘입니다.

Streaming KPIDeveloper

개발 기능 요약

대량의 실시간 설비 데이터 스트림에서 Cycle Time, Queue Time의 백분위수(P99 극단값 필터링 및 P50 중앙값 검출)를 추정하여 성능가동율을 정밀하게 산출할 때 활용됩니다.

핵심 로직: 용량 초과 시 Level i의 버퍼를 정렬하고, 동전 던지기 b \in \{0,1\}에 따라 홀수/짝수 번째 값만 상위 Level i+1로 보내 가중치 2배 부여

알고리즘 상세 개요

1. 실시간 스트림 환경에서의 Quantile 추정 문제

반도체 FAB 공정이나 대형 IT 분산 환경에서 발생하는 대용량 센서 로그 및 이벤트 스트림에서 특정 시간 윈도우의 백분위수(Quantiles, p50 중위값, p95/p99 극단값 등)를 추정하는 것은 매우 중요합니다. 예를 들어, 설비 가동 효율을 높이기 위해 Cycle Time의 99% 선에 달하는 이상치를 필터링하거나 데이터의 중앙값을 참 속도로 대입해야 합니다.

⚠️ 기존 방식의 치명적인 한계

정렬 기반 나이브 방식(Naive Sorting): 들어오는 원시 데이터를 메모리에 모두 보관하고 매번 정렬할 경우, 데이터 수 $N$에 대해 메모리 공간 복잡도 $O(N)$ 및 시간 복잡도 $O(N \log N)$이 요구됩니다. 수천만 건에 달하는 실시간 스트림 환경에서는 메모리 오버플로우가 즉각적으로 발생합니다.

2. KLL (Karnin-Lang-Liberty) 알고리즘 개요

KLL은 2016년에 발표된 스트리밍 분위수 추정 알고리즘으로, 이론상 최적에 수렴하는 공간 복잡도 하한선을 달성했습니다. 전체 데이터를 보관하는 대신, 용량이 각기 다른 여러 단계의 계층형 버퍼(Hierarchical Buffers, Levels)를 두고 데이터를 선별적으로 거르면서(Eviction) 상위 레벨로 밀어 올리는 확률적 축소 메커니즘을 사용합니다.

3. 분위수 추정 알고리즘 스펙 비교

알고리즘 명칭 공간 복잡도 (메모리) 오차 범위 보장 병합 가능성 (Mergeable) 수학적 특징 및 실무 한계
나이브 정렬 (Naive) $O(N)$ (무제한) 완벽함 (오차 0%) 아니오 스트림이 커질수록 메모리 고갈. 실시간 대용량 모니터링 시스템에는 적용 불가.
Greenwald-Khanna (GK) $O(\frac{1}{\epsilon} \log(\epsilon N))$ 결정론적 오차 $\epsilon$ 보장 매우 어려움 결정론적으로 정확한 경계 오차를 제공하지만, 두 개의 Sketch를 중앙 서버에서 병합(Merge)하는 성능이 매우 낮아 분산 노드 분석에 불리함.
T-Digest $O(\text{고정 센트로이드 수})$ 경계면(p01, p99) 오차 극소화 예 양 끝단의 분위수를 매우 정교하게 짚어내어 금융/성능 로그에서 인기가 높으나, 수학적/최악의 시나리오 하에서 엄밀한 에러 바운드 가이드라인 증명이 약함.
KLL Sketch (본 알고리즘) $O(\frac{1}{\epsilon} \log \log \frac{1}{\epsilon})$ 확률론적 오차 $\epsilon$ 보장 예 (완벽한 병합 지원) 이론상 공간 복잡도의 최적 하한선을 달성. 여러 에지 장비에서 수집된 KLL Sketch들을 추가 오차 왜곡 없이 중앙 서버에서 즉각 병합 가능. Apache DataSketches 표준 내장.

4. KLL 계층형 버퍼 및 레벨 스케줄링 구조

KLL은 내부적으로 $0$부터 $H$까지의 계층화된 레벨(Levels)을 관리합니다. 각 레벨 $i$는 동일한 데이터 $k_i$개를 담는 임시 메모리 버퍼를 유지하며, 레벨이 깊어질수록 포함된 데이터들의 **통계적 가중치(Weight)**는 $2^i$배로 정확히 기하급수적으로 증가합니다.

  • Level 0 (원시 유입 버퍼): 원시 스트림 데이터가 가중치 $1$ ($2^0$)을 가진 상태로 최초 수집 및 기록되는 공간입니다.
  • Level i (압축 전이 버퍼): 하위 레벨로부터 무작위 압축(Compaction) 처리를 받아 올라온 값들이며, 데이터 1개당 가중치 $2^i$를 지닙니다.
  • 레벨별 한계 용량 설정 ($k_i$): 메모리 낭비를 줄이기 위해 상위 레벨로 이동할수록 각 레벨의 버퍼 한계 크기를 약 $2/3$ 비율로 점진적으로 감소시킵니다.
    $$k_i = \lfloor k \cdot c^{H-i} \rfloor \quad (c \approx 2/3, \ H \text{는 최대 레벨 수})$$

개발 DFD

상세 작동 단계

KLL 알고리즘의 무결성(Unbiased Estimation)을 유지하며 메모리를 일정량 이하로 고정시키는 핵심 동력은 **확률적 압축(Compaction) 루프**에 있습니다.

  1. 압축 트리거 조건 감지 (Triggering)

    새로운 데이터가 주입되어 특정 레벨 $i$의 현재 데이터 개수가 미리 계산된 허용 임계 용량 $k_i$를 초과하는 즉시 압축 프로세스가 백그라운드에서 실행됩니다.

  2. 버퍼 정렬 및 공간 배치 (Sorting)

    해당 레벨 $i$ 버퍼 안에 저장되어 있는 모든 숫자 데이터들을 오름차순으로 완벽히 정렬하여 가상 수직선 상에 배치합니다.

    $$X_{\text{level } i} = \{x_1, x_2, \dots, x_{2n}\} \quad (x_1 \le x_2 \le \dots \le x_{2n})$$

  3. 무작위 동전 던지기 기반 편향 방지 제거 (Randomized Selection & Eviction)

    정렬된 $2n$개의 데이터 쌍에 대해 확률적 편향(Unbiased Estimate)을 방지하기 위해 물리 공정한 동전 던지기 결과인 임의의 비트 $b \in \{0, 1\}$를 하나 생성합니다.

    • $b = 0$ 인 경우 (짝수 인덱스 승격): 홀수 번째 위치한 데이터들을 메모리에서 완전히 소거하고, 짝수 번째 데이터 $\{x_2, x_4, x_6, \dots\}$만을 선택하여 상위 레벨 $i+1$ 버퍼로 이송합니다.
    • $b = 1$ 인 경우 (홀수 인덱스 승격): 짝수 번째 위치한 데이터들을 메모리에서 완전히 소거하고, 홀수 번째 데이터 $\{x_1, x_3, x_5, \dots\}$만을 선택하여 상위 레벨 $i+1$ 버퍼로 이송합니다.
    • 이 과정을 거치면 레벨 $i$의 데이터 개수는 즉시 절반으로 경감되어 새로운 유입 버퍼 공간을 확보하게 됩니다.
  4. 보존성 가중치 갱신 (Weight Update)

    상위 레벨 $i+1$로 승격되어 올라간 데이터들은 이제 이전보다 2배에 해당하는 가중치 $2^{i+1}$를 새로이 부여받습니다. 비록 원시 데이터의 절반이 탈락하여 정보 손실이 발생했으나, 살아남은 인자가 2배의 가중치 역할을 대리하므로 수학적 기댓값(Expected Cumulative Distribution Function)은 왜곡 없이(Unbiased) 유지됩니다.

  5. 분위수 근사 계산 및 랭크 질의 (Rank & Quantile Query)

    사용자가 특정 분위수 $p$ (예: $0.99$ 분위값)를 질의하면, KLL 스케치 내부의 모든 레벨에 흩어져 있는 잔여 인자들을 가중치 정보와 함께 단일 배열로 결합 및 정렬합니다. 이후 누적 가중치의 누적합(CDF)을 계산하여 목표 랭크에 도달하는 값을 반환합니다.

    $$\text{추정 랭크 } \hat{r}(v) = \sum_{x \in \text{Sketch}, x < v} w(x) \qquad \hat{q}(p) = v \text{ such that } \hat{r}(v) \approx p \cdot N$$

수학적 오차 보장 및 분석

1. 메모리 절약과 오차율($\epsilon$) 보장에 대한 이론적 증명

KLL Sketch가 널리 쓰이는 이유는 사용자가 요구하는 최대 분위수 오차 범위 $\epsilon$에 대해 **필요한 메모리 공간의 상한선이 하드웨어 수준에서 사전에 예측 및 고정 가능함**을 수학적으로 완전 증명했기 때문입니다.

  • 오차율의 수학적 정의:

    전체 데이터 수 $N$에 대해 임의의 백분율 $p \in [0, 1]$을 질의했을 때, KLL Sketch가 반환하는 추정 값 $\hat{q}(p)$의 실제 누적 순위(Rank)는 다음과 같은 오차 경계를 절대로 벗어나지 않습니다.

    $$\text{Pr}\left( \left| \text{Rank}( \hat{q}(p) ) - p \cdot N \right| \le \epsilon \cdot N \right) \ge 1 - \delta$$

    여기서 $\epsilon$은 오차 한계(예: $\epsilon = 0.01$ 이면 실제 백분위수 대비 $\pm 1\%$ 오차 보장)이며, $\delta$는 무작위 압축 실패 확률(통상 $10^{-6}$ 이하의 극소값 설정)입니다.

  • KLL의 엄밀한 공간 복잡도 상한선:

    허용 오차율 $\epsilon$과 신뢰 상수 $\delta$가 주어졌을 때, KLL Sketch를 유지하기 위해 예약해야 하는 최대 활성 데이터 정점의 개수 $M$은 다음과 같습니다.

    $$M = O\left(\frac{1}{\epsilon} \log \log \frac{1}{\epsilon}\right)$$

    이는 기존 GK 알고리즘의 $O(\frac{1}{\epsilon} \log \epsilon N)$과 비교하여 **유입 데이터 수 $N$에 완전히 독립적(N-independent)**이라는 파격적인 이점을 지닙니다. 즉, 데이터가 무한대로 유입되는 반영구적 대용량 설비 스트림 분석에서도 메모리가 단 1바이트도 추가로 증가하지 않고 항상 고정적인 초경량 크기(예: 1% 오차 보장 시 약 1.2KB)를 안전하게 유지합니다.

실시간 설비 OEE 적용 시나리오

KLL Sketch는 반도체 제조 현장의 초고속 데이터 스트리밍 파이프라인에서 메모리와 속도 제약을 완벽하게 조율하며 활용됩니다.

  • SEMI E116 / E10 표준 기반 실시간 설비 Cycle Time의 극단값 필터링 및 대표 성능 산출

    웨이퍼 1장당 공정 진행에 소요되는 시간인 Cycle Time(CT)이나 설비 로봇 팔의 이송 대기 시간인 Queue Time(QT)은 정규 분포를 따르지 않고 극단적인 우측 롱테일(Long-tail) 형태를 띱니다. 레시피 체인지나 기계적 마찰, 알람 상황(SEMI E10 Down)으로 인해 수시간 동안 멈춘 스파이크 데이터가 혼입되면 산술 평균값은 즉각적으로 오염됩니다.

    KLL Sketch를 각 설비별 Edge 수집 모듈에 1KB 크기의 저메모리로 상주시켜 CT의 실시간 $p50$ (중앙값)과 $p99$ (99% 임계값)를 동적으로 추정합니다. p99를 초과하는 비정상 데이터는 장비 병목 및 에러 지연으로 자동 필터링 처리하고, 오염되지 않은 p50 중앙값만을 설비 OEE(종합효율, SEMI E79)의 실시간 가동 효율 속도인 실제 가공율의 대리 지표로 활용하여 정밀도를 비약적으로 높입니다.

  • 고대역폭 장비 데이터 수집(Interface A) 센서 주파수 요약 및 RDBMS 보관비 절감

    SEMI E134 수집 계획에 따라 온도, 유량, RF Reflectance 등 수백 개의 아날로그 센서 데이터가 매초 1,000건씩 쏟아질 때 이를 전부 DB에 인서트하면 스토리지 유지비용이 기하급수적으로 폭증합니다.

    KLL Sketch를 이용해 인메모리에서 초단위 요약 데이터 스트림을 형성합니다. 하루 종일 들어오는 원시 데이터 86,400,000개의 상태 스케치를 직렬화(Serialization)하면 불과 수십 KB의 직렬화 바이너리 블록(`kll_sketch_state` 테이블의 `serialized_blob` 컬럼) 하나로 축소되어 관계형 DB에 저장이 가능하므로, 99.9% 이상의 스토리지 용량을 절감하면서도 임의 시점의 통계 분포를 마이크로초 이내로 정확히 복원해 냅니다.

  • 다중 챔버(Chambers) 개별 상태의 실시간 전역 병합 (FAB-wide Mergeability)

    KLL Sketch는 수학적으로 가산성(Additivity/Mergeability)을 지닙니다. 즉, FAB 내에 분산되어 있는 100대의 CVD Chamber가 각각 수집 및 빌드한 KLL Sketch 상태 파일들을 중앙 클라우드 분석 서버로 보내오면, 분석 서버는 어떠한 원시 데이터 로그도 가져올 필요 없이 100개의 Sketch 객체를 1ms 만에 상호 합산(Merge) 연산 처리합니다.

    병합된 결과는 전체 100대 설비 라인의 전체 데이터 1억 개를 한 번에 넣고 정렬한 것과 동일한 확률적 오차 범위 $\epsilon$ 내에서 동일한 전체 분위수 분포 곡선(FAB-wide Cumulative Profile)을 완벽하게 재구성하므로 분산 빅데이터 처리에 극도로 강력합니다.

KLL & Chan 기반 설비 효율 분석 통합 로직 및 아키텍처

설비 상태 및 효율에 기반하여 대규모 설비 데이터 스트림을 처리하기 위해, Chan's Algorithm(기하학적 경계 산출)과 KLL Sketch(통계적 분포 추정)를 결합한 통합 이상치 제거 및 성능 지표 산출 로직을 설계합니다. 이 통합 로직은 다차원 데이터의 경계(Hull)와 단일 변수의 분포(Quantile)를 모두 고려하여 정교하게 이상치를 필터링하고, 최종적으로 정확한 성능 효율(Performance Efficiency)을 계산하는 데 초점을 맞춥니다.

1. 통합 분석 로직 개요

  • E10 RUN Filter: 설비 상태가 'PRD(Production)'인 유효 가동 시간 데이터만 추출합니다.
  • Chan Engine: 다차원 공정 파라미터(예: 온도 vs 압력)의 기하학적 정상 가동 범위(Operating Envelope)를 계산하여 외곽점(Outlier)을 감지합니다.
  • KLL Engine: 성능 효율의 핵심 지표인 Cycle Time(CT)에 대한 실시간 백분위수(P99, Median)를 추정합니다.
  • 이중 이상치 제거: 신규 데이터 x에 대해 기하학적 정상 가동 범위 내부에 있고, Cycle Time이 P99 임계값보다 작은 경우에만 '정상 데이터 D_clean'으로 판별합니다.
    $$D_{clean} = \{x \in D \mid (isInside(H, x.v)) \land (x.CT < \hat{q}_{0.99})\}$$
  • E79 성능 효율 산출: 정상 데이터 D_clean의 KLL 추정 중위수(Median CT, $\hat{q}_{0.50}$)를 실제 속도로 사용하여 성능가동율을 산출합니다.
    $$\text{성능가동율} = \frac{\text{Theoretical Cycle Time (TCT)}}{\hat{q}_{0.50}} \times 100(\%)$$

2. 설비 효율 분석 시스템 아키텍처

  • Edge Network (데이터 수집): 설비(PLC/GEM)로부터 SECS/GEM 프로토콜을 통해 실시간 상태(E10), 공정 변수, Cycle Time을 Edge Gateway가 수집하여 전송합니다.
  • Stream Processor (실시간 분석 계층): 스트림 처리 엔진 내에서 Chan Engine과 KLL Engine이 각각 기하학적 경계와 통계적 분포를 모델링하고, 통합 필터를 통해 스파이크성 에러와 가짜 데이터를 차단합니다.
  • MES DB / RDBMS: 정제된 성능 지표, E10 상태 로그, 최신 요약본(Convex Hull 정점 및 KLL Sketch 요약본)을 안정적으로 저장합니다.
  • OEE Calculator & Dashboard (시각화 계층): 정제된 실제 속도와 SEMI Product Time 기반의 표준시간(Standard Time)을 비교하여 종합설비효율(OEE)을 산출하고 운영자에게 실시간으로 공유합니다. (양품율은 배제하고 시간가동율과 성능가동율의 곱으로만 OEE 계산)
