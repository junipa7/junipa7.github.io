SEMI E4 (SECS-I)

반도체 장비와 호스트 간의 물리적 연결을 정의하는 클래식 시리얼 통신 표준입니다. RS-232 하드웨어를 기반으로 하며, 저속이지만 신뢰성 있는 포인트 투 포인트(Point-to-Point) 메시지 전송을 보장합니다.

Serial Communication RS-232 Protocol Layer 1 Legacy Protocol

메시지 전송 흐름 (Detailed DFD)

ENQ Signal Handshake
→
EOT Ready Acknowledge
→
Block Send 10+N Bytes
→
Checksum 16-bit Sum
→
ACK/NAK Result

이 다이어그램은 SECS-I의 '핸드쉐이크' 및 '블록 전송' 메커니즘을 시각화한 것입니다.

  • 1. ENQ Signal: 데이터를 보내려는 측(Sender)이 채널 사용권을 요청하기 위해 ENQ(05H)를 보냅니다.
  • 2. EOT Ready: 받을 준비가 된 측(Receiver)이 EOT(04H)로 응답하여 채널이 확보됩니다.
  • 3. Block Send: 길이(1), 헤더(10), 데이터(N) 순서로 구성된 블록을 전송합니다. (최대 254바이트 데이터)
  • 4. Checksum: 전송된 모든 바이트의 단순 합계를 계산하여 데이터 무결성을 검사합니다.
  • 5. ACK/NAK: 수신측이 체크섬 확인 후 정상(ACK) 또는 오류(NAK)를 Sender에게 통보합니다.

SECS-I 블록 구조 (Block Structure)

하나의 SECS-I 블록은 다음과 같은 엄격한 바이트 구조를 가집니다.

필드명 크기(Bytes) 범위 설명
Length 1 10 - 254 헤더(10) + 데이터(N)의 총 길이
Header 10 - Device ID, Message ID, System Bytes 등 포함
Data N 0 - 244 실제 전송될 SECS-II 메시지 데이터 내용
Check Sum 2 - 전송된 모든 바이트의 합계 (Length 제외)

SECS-I의 4대 핵심 타임아웃 (T1 ~ T4)

T1 (Inter-character) 한 블록 내에서 인접한 두 문자 사이의 시간 간격을 제한합니다. 노이즈 등으로 문자 유실 시 감지용입니다.
T2 (Protocol) 핸드쉐이크 시 ENQ에 대한 EOT 응답, 또는 블록 전송 후 ACK/NAK 응답을 기다리는 시간입니다.
T3 (Reply) 메시지 전송 완료 후 상대방으로부터 SECS-II 상의 답변(Reply Message)을 기다리는 시간입니다.
T4 (Inter-block) 멀티 블록 메시지 전송 시, 각 블록 간의 전송 간격을 제한합니다.

충돌 해결 메커니즘 (Contention Handling)

양방향 동시 전송 시도를 'Contention'이라고 하며, SECS-I은 이를 다음과 같이 해결합니다.

  • 우선순위 결정: 통신 설정 시 한쪽은 Master, 반대쪽은 Slave로 설정합니다.
  • 해결 방식: 동시에 ENQ를 보냈을 경우, Master가 보낸 ENQ를 Slave가 수용(EOT)하고 자신의 전송을 뒤로 미룸으로써 충돌을 회피합니다.
