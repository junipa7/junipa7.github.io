1장. SEMI E132 (Authentication & Authorization) 개요

SEMI E132는 EDA(Interface A) 통신 환경에서 장비와 호스트 클라이언트 간의 인증(Authentication), 권한 제어(Authorization), 세션 관리(Session Management)를 규정하는 보안 표준입니다. HTTP/SOAP 통신을 기반으로 하는 Interface A가 무분별한 데이터 접근과 해킹으로부터 보호받을 수 있게 하는 방패 역할을 합니다.

2장. 핵심 메커니즘

1. Authentication (인증)

이 클라이언트가 정말로 접근 자격이 있는 시스템인지 확인합니다. E132는 SSL/TLS 기반의 X.509 상호 인증서(Mutual Certificate) 기반 인증을 강력히 권장합니다. 장비와 클라이언트가 서로의 인증서를 교환하고 신뢰할 수 있는지 검증합니다.

2. Authorization (권한 부여) 및 ACL

인증된 클라이언트라 하더라도 모든 데이터를 마음대로 빼갈 수는 없습니다. 장비 내부에는 ACL (Access Control List)이 존재하며, 각 클라이언트(Role)별로 다음과 같은 권한을 세밀하게 통제합니다.

  • 어떤 서브시스템(예: PM1, PM2)의 데이터에만 접근할 수 있는가?
  • 초당 최대 몇 개의 파라미터를 수집(Trace)할 수 있는가?
  • 새로운 데이터 수집 플랜(DCP)을 생성하거나 삭제할 권한이 있는가?

3. Session Management (세션 관리)

클라이언트가 장비에 성공적으로 인증되면 Session ID를 발급받습니다. 이후의 모든 데이터 구독(Subscription) 및 모델 조회 요청은 이 Session ID를 통해 이루어집니다. 세션 타임아웃이 발생하면 재인증을 받아야 합니다.

3장. E132 통신 핸드쉐이크 흐름

  1. 클라이언트가 장비에 EstablishSessionRequest 전송 (자신의 인증서 정보 포함).
  2. 장비는 클라이언트의 ACL을 확인하고 Session ID를 담아 EstablishSessionResponse 반환.
  3. 클라이언트가 이 Session ID를 가지고 GetEquipmentModel(E120/125) 등 실제 업무 요청 진행.
  4. 연결 종료 시 TerminateSessionRequest를 통해 세션 자원 반환.

4장. 실무 적용 시 트러블슈팅

SSL/TLS 인증서 만료 가장 흔히 발생하는 장애입니다. 테스트망에서 발급한 사설 인증서의 유효기간이 1년이 지나 만료되면서 갑자기 통신이 전면 중단됩니다. 팹 인프라 부서와 연계하여 인증서 자동 갱신 프로세스나 유효기간 알람 모니터링을 반드시 구축해야 합니다.
ACL 설정의 휴먼 에러 장비 엔지니어가 장비 UI 화면에서 클라이언트의 권한(ACL) 맵핑을 누락하거나 잘못된 Role을 부여하여 Access Denied 에러가 빈발합니다. 보안 상의 이유로 에러 메시지가 구체적이지 않기 때문에 장비 측 보안 로그를 함께 분석해야 합니다.
