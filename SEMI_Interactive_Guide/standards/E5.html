4 데이터 흐름 (DFD)

장비 컨트롤러가 수집한 미가공 상태 변수와 알람 정보가 SECS-II 메시지로 캡슐화되어 호스트 EAP를 거쳐 MES 및 상위 시스템에 수집되는 전체 논리 흐름도입니다.

5 현장 실무 트러블슈팅 및 예외 룰

현장 셋업과 반도체 설비 통신 구축 시 빈번하게 충돌하는 오류 사례와 정합성 기준 대처 방안입니다.

메시지 정합성 예외 상황 대처

SECS-II는 포맷과 배열 크기가 엄격히 준수되어야 합니다. 그렇지 않으면 드라이버 계층 혹은 EAP 시스템 전체가 다운되거나 오작동을 유발합니다.

상황 A: List Count 불일치 및 Parser Exception

호스트 EAP 드라이버가 정의서상의 List 포맷 [L, 3]을 예상했으나, 장비가 파라미터 유실 등의 이유로 [L, 2] 혹은 빈 리스트 [L, 0]을 보내 수신 스레드가 폭발(NullPointerException 등)하는 경우입니다.

➔ 메시지 정의 시 가변 리스트 사용을 최소화하고, 가용 데이터가 없더라도 구조 유지를 위해 자리표시자(Empty ASCII 등)를 필수 주입
상황 B: 숫자형 데이터 타입(Integer vs Float) 해석 불일치

장비 제어 보드 내부에서는 온도를 4바이트 정수형(I4)으로 가공해 전송하는데, 호스트 정의서에서는 4바이트 실수형(F4)으로 설정하여 해석 결과가 완전히 왜곡되는 현상입니다.

➔ EAP/EES 인터페이스 구축 초기 단계에서 데이터 사전(secs_item_dictionary)과 실제 장비 송출 포맷을 1:1 일치시키고 검증 바이트 대조 검사 선행

SECS-II 트랜잭션 흐름 분석

SECS-II 메시지가 대화(Transaction) 세션을 구성하며 응답을 처리하는 정합성 상태 룰입니다.

구분 기준 Primary Message (SxFy) Secondary Message (SxFy+1)
트랜잭션 시작자 질의 또는 이벤트를 보낼 때 먼저 전송하는 주도측 (홀수 펑션 번호: y) 질의를 받고 대답하는 피동측 (짝수 펑션 번호: y+1)
W-Bit 제어 룰 W-Bit = 1 (응답 요구)
W-Bit = 0 (응답 불필요)		 W-Bit = 0 (고정)
항상 단방향 완료 처리
System Bytes 매칭 새로운 고유 트랜잭션 번호 생성 및 할당 (4 Bytes) 상대측 Primary와 **완벽히 동일한** System Bytes 값을 헤더에 박아 전송
시간 제한 (Timeout) 보내고 난 후 T3 타이머 만료 전까지 Secondary를 대기해야 함 Primary 접수 후 빠르게 처리하여 T3 지연을 방어해야 함

E5 데이터 정합성 검증 의사코드 (Pseudo-code)

// ==========================================
// 함수: handleE5Event
// 목적: SECS-II 메시지 바디 데이터의 유효성 검증
// 매개변수: event (SECS-II 수신 이벤트 객체)
// 반환값: 에러 코드 또는 정상 완료 상태
// ==========================================
function handleE5Event(event):
    // 1. 기본 장비 식별 값 및 시간의 정합성 유효성 체크
    assert event.equipmentId is not empty
    assert event.eventTime is not in the future
    
    // 2. 바디에 담겨 날아온 리스트 포맷 무결성 검사
    // SECS-II 파싱 엔진이 원본 바이트에서 리스트를 파싱 완료했는지 확인
    if event.bodyList == null or length(event.bodyList) == 0:
        logError("수신 거부: SECS-II 데이터 바디가 비어있거나 올바르지 않은 리스트 구조입니다.")
        return ERROR_EMPTY_BODY
        
    // 3. 기대 리스트 크기 검사 (List Count Mismatch 탐지 예시)
    // S6F11의 경우 3개의 기본 리스트 요소 [DATAID, CEID, RPT]를 가짐
    expectedListCount = 3
    if length(event.bodyList) != expectedListCount:
        logError("정합성 불일치: S6F11 리스트 카운트 오류입니다.")
        logError("기대 크기: " + expectedListCount + ", 실제 크기: " + length(event.bodyList))
        return ERROR_LIST_COUNT_MISMATCH
        
    // 4. 개별 데이터 아이템의 타입 포맷 무결성 대조 검증
    // 첫 번째 인자인 DATAID가 4바이트 부호 없는 정수(U4) 또는 1바이트 바이너리(B) 형식인지 대조
    dataIdFormat = getSecsFormatCode(event.bodyList[0])
    if dataIdFormat != FORMAT_U4 and dataIdFormat != FORMAT_BINARY:
        logError("타입 불일치: DATAID 변수 타입 포맷 오류입니다.")
        return ERROR_FORMAT_CODE_MISMATCH
        
    // 5. 검증을 모두 정상 통과한 경우, 로깅 및 하위 GEM 디코더로 라우팅
    saveRawEvent(event)
    publishToGemProcessor(event.bodyList)
    
    return STATUS_SUCCESS
