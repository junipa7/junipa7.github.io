1장. SEMI E134 (Data Collection Management) 개요

SEMI E134는 EDA 클라이언트가 장비에게 "어떤 데이터를, 언제, 얼마나 자주, 어디로 보내줄 것인가"를 지시하고 구독(Subscription)하는 방식을 정의합니다. 기존 SECS/GEM의 다이내믹 이벤트 리포팅(S2F33 등)과 Trace 데이터(S6F1)를 통합하고 발전시킨, Interface A의 핵심 데이터 수집 엔진입니다.

2장. Data Collection Plan (DCP)의 구조

데이터 수집의 단위를 DCP라고 부르며, 호스트는 장비 내부에 여러 개의 DCP를 심어놓을 수 있습니다. DCP는 두 가지 핵심 요소로 구성됩니다.

1. Trigger (언제 수집을 시작하고 멈출 것인가?)

데이터를 수집하는 타이밍입니다. 불필요한 데이터를 계속 받지 않기 위해 정교한 조건을 설정할 수 있습니다.

  • Event-based: 장비 상태가 변하거나 특정 공정 단계가 시작될 때 수집.
  • Time-based: 0.1초(10Hz) 등 주기적으로 수집.
  • Condition-based: "챔버 온도가 100도를 넘을 때" 수집 시작.

2. Report Group (무엇을 보낼 것인가?)

트리거가 작동했을 때 보낼 데이터의 묶음입니다. 장비 전체의 데이터가 아니라, E120/E125 모델을 바탕으로 특정 파라미터(예: PM1의 온도, 가스량)들만 명시적으로 골라서(Select) 지정합니다.

3장. E134의 주요 이점 (SECS/GEM 대비)

왜 기존 S6F1/S6F11을 놔두고 E134를 사용할까요?

  • 초고속 샘플링 (High-Frequency Data): SECS-II의 초당 1회 샘플링을 넘어, E134는 초당 10회, 100회(10Hz~100Hz) 이상의 미세한 센서 데이터를 안정적으로 수집할 수 있어 정밀한 FDC(고장 감지) 모델링이 가능합니다.
  • 멀티 클라이언트 지원: SECS/GEM은 1:1 통신만 지원하지만, E134(EDA)는 여러 대의 클라이언트 시스템(예: FDC용 서버, APC용 서버, R&D용 서버)이 각각 독립적인 DCP를 생성하여 간섭 없이 데이터를 수집할 수 있습니다.
  • 데이터 타임스탬프 정확도: 수집된 데이터에 밀리세컨드 단위의 발생 타임스탬프가 붙어 있어 인과관계 분석에 탁월합니다.

4장. 실무 적용 및 트러블슈팅

Bandwidth 제한과 장비 부하 (Throttling) 100Hz로 수백 개의 파라미터를 요청하면 장비 컨트롤러의 CPU가 마비될 수 있습니다. E132 ACL 설정에서 최대 수집 용량을 제한해야 하며, 호스트도 꼭 필요한 공정 스텝(Step) 구간에서만 수집(Trigger)되도록 DCP를 효율적으로 설계해야 합니다.
DCP Lifecycle 관리 클라이언트가 강제로 종료되어 RemoveDCP 메시지를 보내지 못하면, 장비 내부에 불필요한 고아(Orphan) DCP가 계속 쌓여 자원을 낭비합니다. 장비 단에서 세션 타임아웃 시 DCP를 자동 정리하거나, 클라이언트 재접속 시 기존 DCP를 덮어쓰는(Overwrite) 로직 점검이 필수입니다.
