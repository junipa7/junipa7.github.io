2. 운영 데이터가 KPI가 되는 흐름

1. DefineE172/E173으로 변수와 메시지 의미를 정의합니다.
2. CollectSECS/GEM 또는 EDA로 이벤트, 상태, trace 데이터를 수집합니다.
3. QualifyE151/E160 관점으로 누락, 지연, 대체값, 신뢰도를 표시합니다.
4. MeasureE10/E116으로 가동, 성능, 신뢰성, 설비 손실을 계산합니다.
5. ProtectE187 기준으로 장비 접속, 계정, 네트워크, 변경 위험을 통제합니다.

4. 같이 봐야 하는 이유

사전 없는 KPI는 유지보수 비용이 큽니다.

변수 의미가 장비마다 다르면 E10/E116 계산 로직이 설비별 예외 처리로 무너집니다.

품질 없는 데이터는 분석을 흔듭니다.

누락, 지연, invalid 값을 구분하지 않으면 FDC/APC와 OEE가 잘못된 결론을 낼 수 있습니다.

보안 없는 연결은 운영 리스크입니다.

장비 네트워크와 계정 관리가 약하면 데이터 수집 경로가 공격면이 됩니다.

Productivity는 상태 정의에서 시작합니다.

가동/비가동/엔지니어링/스탠바이 시간의 정의가 맞아야 KPI가 현장 언어와 맞습니다.
