1장. SEMI E120 (Common Equipment Model) 개요

SEMI E120은 장비의 구조를 XML 기반의 트리 구조로 모델링(계층화)하는 표준입니다. 기존 SECS/GEM 환경에서는 장비 내부 데이터가 평면적이고 파편화되어 있어 어떤 데이터가 어느 모듈에서 나온 것인지 직관적으로 알기 어려웠습니다. E120은 "이 장비는 어떤 모듈들로 구성되어 있고, 각 모듈에는 어떤 컴포넌트가 있는가"를 정형화하여 호스트(Client)에게 제공하는 EDA(Interface A)의 뼈대 역할을 합니다.

2장. CEM 트리 구조 (Hierarchy)

모든 장비는 다음과 같은 노드(Node) 타입들로 계층 구조를 이루어야 합니다.

  • Equipment: 최상위 노드. 팹 내의 개별 설비 전체를 의미합니다.
  • Subsystem: 장비를 구성하는 주요 기능적 덩어리. (예: Load Port, Transfer Module, Process Module)
  • Component: Subsystem을 이루는 하드웨어/소프트웨어 부품. (예: Robot Arm, Heater, Throttle Valve)
  • IOMdl (Input/Output Module): 센서, 액추에이터 등 데이터를 직접 주고받는 말단 장치.
이 계층 구조 덕분에, 호스트는 "Process Module 1의 Heater 2번의 온도 센서"라는 식으로 경로를 명확하게 추적할 수 있습니다.

3장. State Machine (상태 머신) 통합

E120 모델의 또 다른 장점은 상태 머신(State Machine)의 투명성입니다. SECS/GEM 시절 문서에만 존재하던 장비의 각종 상태 모델(E90 Substrate 상태, E87 Carrier 상태, E40 Job 상태 등)을 XML 모델 안에 명시적으로 포함시킵니다.

호스트는 장비의 E120 모델만 다운로드하여 분석하면, "이 장비의 1번 Load Port는 현재 IDLE 상태이고, 상태 전이 조건은 A, B, C가 있구나"를 자동으로 파악할 수 있게 됩니다.

4장. 실무 적용 및 트러블슈팅

모델 갱신과 호환성 (Model Versioning) 장비의 하드웨어가 개조되거나 펌웨어가 업데이트되어 센서가 추가되면 장비 모델 트리(CEM)도 변합니다. E120은 이러한 변경 시 모델 버전(Model Version)을 올려 호스트에게 통보하도록 규정하고 있습니다. 클라이언트는 캐싱된 이전 버전 모델로 데이터를 요청하면 에러가 발생하므로 주기적인 동기화가 필요합니다.
SECS/GEM과의 병행 운영 E120 모델 내의 노드들은 기존 SECS/GEM의 SVID, CEID와 매핑 정보를 가질 수 있습니다. 이를 통해 레거시 시스템과 신규 EDA 시스템을 동시에 운영할 때 데이터의 출처를 상호 대조(Cross-reference)할 수 있습니다.
