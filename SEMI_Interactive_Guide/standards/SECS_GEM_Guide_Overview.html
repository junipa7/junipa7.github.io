SECS/GEM Guide Overview

SEMI E4, E5, E30, E37을 따로 외우기보다 “전송 방식 - 메시지 문법 - 장비 업무 모델”의 관계로 먼저 이해하는 입문 지도입니다.

E4: SECS-I E37: HSMS E5: SECS-II E30: GEM

1. 한 장으로 보는 관계

E30은 업무 규칙 E5는 메시지 언어 E4/E37은 운반 방식

2. 통신을 계층으로 쌓아 보기

E30
무슨 일을 할 것인가?장비 상태 전환, 이벤트 보고, 알람, 변수 조회, 원격 명령 같은 자동화 업무를 정의합니다.
E5
그 일을 어떤 메시지로 말할 것인가?S1F1, S1F13, S2F41처럼 Stream/Function과 데이터 타입으로 대화 문법을 만듭니다.
E4
오래된 직렬선 위로 어떻게 보낼 것인가?RS-232 기반 SECS-I 프레임, ENQ/EOT/ACK/NAK, 타이머와 재전송을 다룹니다.
E37
TCP/IP 네트워크 위로 어떻게 보낼 것인가?HSMS 세션, Select/Separate, Linktest, System Bytes를 통해 같은 E5 메시지를 네트워크로 전달합니다.

3. 같은 메시지, 다른 운반 수단

공통 메시지: E5 SECS-II
S1F13

Host가 장비와 통신을 열기 위해 Establish Communication을 요청합니다.

S1F14

장비가 통신 수립 가능 여부와 결과를 응답합니다.

S6F11

장비가 이벤트가 발생했음을 Host로 보고합니다.

S2F41

Host가 장비에 Remote Command를 전달합니다.

운반 A: E4 SECS-I
직렬 포트

RS-232C 설정, baud rate, parity, stop bit가 중요합니다.

Handshake

ENQ/EOT/ACK/NAK로 한 번에 한 블록씩 안전하게 넘깁니다.

Block

SECS-II 메시지를 작은 블록으로 나누고 checksum을 붙입니다.

Legacy

구형 장비와 긴 수명 주기의 Fab에서 여전히 만날 수 있습니다.

운반 B: E37 HSMS
TCP/IP

이더넷 네트워크와 소켓 연결 위에서 동작합니다.

Select

통신 가능 세션을 선택하고 Selected 상태를 유지합니다.

System Bytes

요청과 응답을 짝지어 transaction을 추적합니다.

Modern

속도, 거리, 운영 편의성 때문에 현재 장비에서 더 일반적입니다.

4. E4/E5/E30/E37 역할 비교

표준 한 줄 역할 주요 질문 예시 키워드
SEMI E4
SECS-I		 직렬선에서 SECS 메시지를 안전하게 주고받는 방법 바이트를 어떻게 블록으로 나누고 재전송할까? RS-232, ENQ/EOT, ACK/NAK, checksum, T1~T4
SEMI E37
HSMS		 TCP/IP에서 SECS 메시지를 세션 기반으로 운반하는 방법 소켓 연결 후 어떤 상태와 제어 메시지가 필요할까? Select, Separate, Linktest, T5~T8, System Bytes
SEMI E5
SECS-II		 장비와 Host가 이해하는 메시지 문법 어떤 Stream/Function과 데이터 타입으로 말할까? SxFy, W-bit, List, Binary, ASCII, U4
SEMI E30
GEM		 장비 자동화가 제공해야 하는 공통 기능 모델 장비 상태, 이벤트, 알람, 명령은 어떤 규칙으로 운영할까? Communication, Control State, Event Report, Alarm, Remote Command

5. 추천 학습 순서

E5 먼저 보기

무엇을 주고받는지 알아야 E4와 E37의 차이가 단순해집니다. SxFy와 데이터 타입부터 잡습니다.

E4와 E37 비교

둘 다 E5 메시지를 운반하지만, E4는 직렬선, E37은 TCP/IP입니다. “운반 수단” 관점으로 비교합니다.

E30으로 업무 연결

메시지가 실제로 어떤 장비 업무를 만드는지 봅니다. 통신이 자동화 기능으로 바뀌는 지점입니다.

현장 로그로 확인

S1F13/S1F14, S6F11, S2F41 같은 로그를 보며 계층별로 문제 위치를 나눠 봅니다.

6. 헷갈리기 쉬운 포인트

E4와 E37은 경쟁 표준이라기보다 전송 선택지입니다.

둘 중 하나를 선택해 E5 메시지를 보냅니다. 어떤 것을 쓰는지는 장비 세대, 네트워크 환경, 벤더 구현에 따라 달라집니다.

E30은 메시지 포맷이 아니라 장비 행동 모델입니다.

E30을 이해하려면 “SxFy 번호 암기”보다 Online 상태, 이벤트 보고, 알람 처리 같은 운영 시나리오를 먼저 보는 편이 좋습니다.
