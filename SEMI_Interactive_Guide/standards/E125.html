1장. SEMI E125 (Equipment Self Description) 개요

SEMI E125는 장비가 스스로 자신이 어떤 파라미터(센서 값)와 이벤트(알람, 상태 변화)를 가지고 있는지 호스트에게 설명서(Metadata) 형태로 제공하는 표준입니다. E120이 장비의 "구조(뼈대)"를 정의한다면, E125는 그 뼈대에 어떤 "데이터(혈관)"가 흐르는지를 기술합니다.

2장. 주요 기술 요소 (Metadata Elements)

장비는 E120의 각 트리 노드마다 E125 기반의 데이터 항목들을 주렁주렁 매달아 놓습니다.

  • Parameters (파라미터): 장비가 제공하는 변수들입니다. 센서 값, 설정 값, 타이머 등이 포함되며, 데이터 타입(정수, 실수, 문자열), 단위(Unit), 최소/최대값 제약 조건 등의 메타데이터를 포함합니다.
  • Events (이벤트): 장비 내부에서 발생하는 사건입니다. 상태 변경, 공정 시작/종료, 에러 발생 등이 정의되며, 이벤트 발생 시 어떤 파라미터 값들을 함께 읽을 수 있는지 연관 관계를 가집니다.
  • Exceptions (예외/알람): 장비의 알람이나 에러 상황을 기술합니다.

3장. Self-Description의 비즈니스적 가치

기존 SECS/GEM에서는 장비의 수만 가지 SVID와 CEID의 의미를 알려면 벤더가 제공하는 두꺼운 엑셀 매뉴얼(GEM Manual)을 사람이 일일이 읽고 EAP 시스템에 타이핑하여 매핑해야 했습니다.

E125가 적용된 EDA 환경에서는 클라이언트(호스트)가 장비에게 "네가 가진 모든 변수와 이벤트 목록의 XML 모델을 줘(GetEquipmentModel)"라고 요청하면 끝납니다. 이로 인해 장비 연동 기간(Integration Time)이 수주에서 수 시간으로 획기적으로 단축됩니다.

4장. 실무 적용 및 트러블슈팅

방대한 XML 크기 처리 최신 장비의 E125 모델 XML 파일은 수십~수백 MB에 달할 수 있습니다. 클라이언트 측 파서(Parser)가 DOM 방식으로 전체 파일을 한 번에 메모리에 올리려다 Out of Memory 에러가 발생하기 쉽습니다. 반드시 SAX나 스트리밍 파서를 사용하여 모델을 파싱하고 로컬 DB에 인덱싱해야 합니다.
동적 파라미터 (Dynamic Parameters) 특정 장비들은 레시피가 실행될 때마다 파라미터 목록이 동적으로 변하는 경우가 있습니다. E125는 정적인 메타데이터를 지향하므로, 동적으로 변하는 구조에 대한 처리는 벤더와의 협의를 통해 Data Collection Plan (E134) 단에서 유연하게 구독할 수 있도록 설계해야 합니다.
