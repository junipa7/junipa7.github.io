1장. GEM300 개요 및 필요성

GEM300은 300mm(12인치) 웨이퍼 팹(Fab)의 완전 자동화(Full Automation)를 달성하기 위해 도입된 SEMI 표준들의 집합체입니다. 기존 200mm 시절의 E30(GEM)만으로는 OHT(천장 반송 장치) 물류 연동과 복잡한 작업 지시를 처리할 수 없어 새롭게 제정되었습니다.

1. 왜 기존 GEM으로는 부족했는가?

200mm 공장에서는 작업자가 손으로 카세트를 나르고 장비 버튼을 눌러 레시피를 실행하는 반자동화가 흔했습니다. 장비 입장에서는 "웨이퍼가 왔네, 굽자" 정도로 충분했습니다. 그러나 300mm 팹에서는 무거운 FOUP을 로봇(OHT)이 나르기 때문에 장비와 OHT 간의 복잡한 물리적 인터페이스(E84)가 필요해졌고, 중앙 시스템이 어떤 FOUP을(Carrier), 어떤 슬롯의 웨이퍼만 골라서(Substrate), 어떤 레시피로 구울지(Job) 매우 정교하게 지시해야 했습니다.

2. 패러다임의 변화: 객체 지향 모델

GEM300은 장비 내부의 요소를 객체(Object)로 정의합니다. 통이나 캐리어는 Carrier Object, 웨이퍼 한 장 한 장은 Substrate Object, 작업 지시서는 Job Object로 취급하며, 호스트는 이 객체들의 상태(State)를 실시간으로 모니터링하고 제어(E39 Object Services)하게 됩니다.

2장. GEM300을 구성하는 핵심 표준들 (Core Suite)

GEM300은 단일 문서가 아니라, 목적에 따라 여러 개의 표준 번호로 나뉘어 유기적으로 맞물려 돌아갑니다.

SEMI E39 (Object Services) GEM300의 근간이 되는 '언어'입니다. 장비 내의 다양한 객체들을 생성(Create), 삭제(Delete), 속성 조회(GetAttr), 속성 변경(SetAttr)하는 공통적인 방법론을 제공합니다.
SEMI E40 (Processing Management) "무엇을 어떻게 가공할 것인가"를 정의합니다. Process Job(PJ) 객체를 통해 특정 웨이퍼들에 어떤 레시피를 적용할지 작업 단위와 상태(Queued, Executing, Completed)를 관리합니다.
SEMI E87 (Carrier Management) "FOUP(자재통)의 움직임"을 관리합니다. 장비의 Load Port에 FOUP이 안착되고, 도어를 열어 슬롯 맵(Slot Map)을 읽고, 작업이 끝나면 OHT가 다시 가져갈 수 있도록 상태(CMS)를 관리합니다.
SEMI E90 (Substrate Tracking) "웨이퍼 개별 추적"을 담당합니다. 챔버 안에서 웨이퍼가 어디에 있는지(At Source, At Process, At Destination)를 정확히 추적하여, 에러 발생 시 어느 웨이퍼가 망가졌는지 파악합니다.
SEMI E94 (Control Job Management) "작업과 물류의 묶음"을 제어합니다. Control Job(CJ)은 하나 이상의 Process Job(PJ)을 묶고, 어떤 Carrier(FOUP)에서 자재를 빼올 것인지 물류와 공정을 연결해 주는 최상위 작업 지시서입니다.
SEMI E116 (Equipment Performance Tracking) 장비 전체뿐만 아니라 장비 내부의 각 모듈(챔버, 로봇 등) 단위의 성능과 상태(E10 상태 모델)를 세밀하게 추적합니다.

3장. GEM300의 일반적인 작업 흐름 (Standard Workflow)

300mm 팹에서 웨이퍼가 장비에 도착하여 가공되고 나갈 때까지, GEM300 표준들이 릴레이로 작동하는 흐름입니다.

  1. OHT 배송 & E87: OHT가 FOUP을 Load Port에 내려놓습니다. 장비는 E87을 통해 호스트에 "FOUP 도착(Carrier Arrived)"을 알립니다.
  2. ID 및 Slot Map 확인 (E87 & E90): 장비가 FOUP의 바코드/RFID를 읽고 호스트에 보고합니다. 문을 열어 25개 슬롯 중 몇 번 슬롯에 웨이퍼가 있는지(Slot Map)를 스캔하여 E90 Substrate 객체로 호스트에 보고합니다.
  3. 작업 지시 하달 (E94 & E40): 호스트가 장비에 Control Job(CJ)과 Process Job(PJ)을 차례로 내려보내(Create) "이 FOUP의 1~5번 웨이퍼를 A레시피로 구워라"라고 지시합니다.
  4. 작업 실행 (E90 & E40): 장비가 PJ를 실행(Executing)합니다. 로봇이 웨이퍼를 챔버로 옮길 때마다 E90을 통해 위치 변경 이벤트가 호스트로 쏟아집니다.
  5. 작업 완료 (E94 & E87): 모든 가공이 끝나면 웨이퍼가 FOUP으로 돌아오고, PJ와 CJ가 완료(Completed) 상태가 됩니다. 장비는 호스트에 완료를 보고하고, 호스트는 OHT를 불러 FOUP을 가져갑니다.

4장. 실무 적용의 어려움과 체크포인트

GEM300은 매우 복잡하여 장비 벤더와 호스트 간의 해석 차이가 자주 발생합니다.

  • State Machine 싱크로율: E87, E90, E40, E94 각각의 상태 머신이 동시에 톱니바퀴처럼 돌아갑니다. 호스트의 타이머가 장비의 응답 속도보다 짧으면 작업이 꼬여서 알람이 대량 발생합니다.
  • Exception Handling (예외 처리): 정상 시나리오(Happy Path)는 구현이 쉽지만, "가공 중 챔버 에러", "로봇 그립 에러", "통신 단절 시 복구" 등 예외 상황에서 각 객체(PJ, CJ, Substrate)의 상태를 깔끔하게 Abort 처리하고 롤백하는 로직이 벤더 기술력의 핵심입니다.
