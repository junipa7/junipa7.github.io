1장. SEMI E37 (HSMS) 개요

SEMI E37은 HSMS(High-Speed SECS Message Services)로, 기존 시리얼 통신(RS-232C) 기반이었던 SECS-I(E4)의 한계를 극복하기 위해 TCP/IP 기반의 고속 통신 프로토콜을 정의한 표준입니다. 이더넷(Ethernet) 위에서 SECS-II 메시지를 어떻게 패키징하고 전송할지 규정합니다.

1. HSMS의 등장 배경

과거에는 장비와 호스트가 시리얼 케이블로 1:1 직접 연결되었으나, 300mm 공장 도입과 함께 엄청난 양의 Trace 데이터와 레시피가 발생하면서 9600bps 속도의 시리얼 통신으로는 감당할 수 없게 되었습니다. HSMS는 이더넷의 속도(10/100/1000Mbps)를 그대로 활용하며, 공장 네트워크망을 통해 여러 장비를 유연하게 연결할 수 있게 해주었습니다.

2장. HSMS 메시지 구조 (Message Format)

HSMS 패킷은 메시지 길이(Message Length) + 헤더(Header) + 실제 SECS-II 데이터(Data)의 3부분으로 구성됩니다.

1. 패킷 구성

  • Message Length (4 bytes): 헤더와 데이터를 합친 총 길이를 나타냅니다. TCP는 스트림 통신이므로 수신 측에서 이 길이를 먼저 읽어 언제 패킷이 끝나는지 파악합니다.
  • Header (10 bytes): Session ID, Stream, Function, P-Type, S-Type, System Bytes 등으로 구성됩니다.
  • Data Text (Variable): SECS-II(E5) 규격으로 인코딩된 실제 데이터. (제어 메시지의 경우 데이터가 없을 수도 있음)

2. Session ID (Device ID)

헤더 앞부분의 2바이트로, 하나의 TCP/IP 포트에서 여러 논리적 장비를 구분할 때 사용됩니다. 일반적인 장비는 0을 사용합니다.

3. System Bytes

메시지의 고유 식별 번호(Transaction ID)입니다. Primary 메시지를 보낼 때 System Bytes를 부여하고, 상대방이 Reply를 보낼 때 동일한 System Bytes를 복사해서 보내어, "이 응답이 어느 요청에 대한 응답인지"를 매핑합니다.

3장. HSMS 통신 연결 절차와 S-Type

HSMS 헤더의 S-Type (Session Type) 값에 따라 메시지가 단순 데이터 전송인지, 통신 제어용인지 구분됩니다.

1. Data Message (S-Type = 0)

우리가 아는 일반적인 SECS-II 메시지(SxFy)를 실어 나르는 상태입니다.

2. Control Messages (S-Type 1~10)

HSMS 자체의 연결과 핑 테스트를 위한 컨트롤 메시지입니다.

  • Select.req (1) / Select.rsp (2): TCP/IP 소켓이 연결(Connect)된 직후, HSMS 논리적 세션을 맺기 위한 요청/응답입니다. (이 절차가 성공해야 S1F13 등 데이터 전송 가능)
  • Deselect.req (3) / Deselect.rsp (4): 논리적 세션을 우아하게 종료할 때 사용.
  • Linktest.req (5) / Linktest.rsp (6): 통신망이 살아있는지 확인하는 하트비트(Heartbeat) 기능입니다. 주기적으로 주고받으며 연결 끊김을 감지합니다.
  • Reject.req (7): 상대방이 이상한 HSMS 헤더 포맷을 보냈을 때 거절하는 메시지.
  • Separate.req (9): 통신을 강제로 끊어버리겠다는 통보입니다.

4장. HSMS 타임아웃 파라미터 (T-Timers)

실무에서 가장 많이 부딪히는 문제가 타임아웃입니다. HSMS는 네트워크 지연과 장비 부하를 고려해 정교한 타이머를 둡니다.

타이머 의미 권장/기본값
T3 (Reply Timeout) Primary 메시지를 보내고 Secondary(응답) 메시지를 기다리는 최대 시간. 45초
T5 (Connect Timeout) TCP/IP 소켓 연결 시도(SYN) 후 성공할 때까지 기다리는 시간. 10초
T6 (Control Timeout) Select.req 등 컨트롤 메시지를 보내고 응답을 기다리는 시간. 5초
T7 (Not Selected Timeout) TCP 소켓은 연결되었는데 상대방이 Select.req를 안 보내고 멍때리는 시간 제한. 초과 시 연결 끊음. 10초
T8 (Network Intercharacter Timeout) 하나의 패킷이 수신되는 도중 다음 바이트가 오기까지의 최대 지연. (네트워크 끊김 감지) 5초
실무 팁: 보통 호스트(TC/EAP)가 Active(Client) 모드로 접속하고 장비가 Passive(Server) 모드로 대기합니다. 통신이 안 될 때 Ping은 가는데 연결이 안 된다면 장비의 Port 번호 설정과 Active/Passive 방향 설정을 확인해야 합니다.
