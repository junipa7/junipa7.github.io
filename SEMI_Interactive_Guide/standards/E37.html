SEMI E37 마스터 가이드 (HSMS)

TCP/IP 기반 초고속 반도체 설비 통신 서비스를 위한 글로벌 표준. 복잡한 세션 상태 전이 기계(State Machine)와 각종 통신 타이머 규격을 직접 모의 시뮬레이션해 보세요.

4 데이터 흐름 (DFD)

설비 측 HSMS Passive 포트 리슨 상태부터 TCP 소켓 핸드셰이크 수립, 그리고 상위 Host Active 연결 시도의 데이터 지향 흐름입니다.

5 현장 실무 트러블슈팅 및 예외 룰

고속 이더넷 망으로 변하면서 현장 셋업 및 공정 기동 시에 빈발하는 통신 오류와 극복 가이드입니다.

세션 제어 정합성 예외 상황

이더넷 기반 HSMS 통신은 물리 속도는 빠르나, 네트워크 구성 요소와 타이머 셋업 오설정으로 인해 대단위 장애가 흔히 납니다.

상황 A: Active / Passive 포트 바인딩 충돌 (TCP 미연결)

양측 장치 엔지니어가 설정 시 통신 역할을 혼동하여 호스트(EAP)와 장비(GEM) 둘 다 Active(클라이언트) 혹은 둘 다 Passive(서버 리슨) 상태로 두어 TCP 포트가 아예 붙지 않는 경우입니다.

➔ 표준 규칙에 맞춰 설비 측을 Passive(포트 리슨: 5001 등), 호스트 EAP 측을 Active로 이원화 설정 확립
상황 B: T7 타임아웃 단절 루프 및 소켓 리소스 고갈

TCP 소켓은 매끄럽게 연결되나, 상위 핸드셰이크 신호인 Select.req를 제한 시간(T7: 10초) 내에 수신하지 못하여 매 10초마다 세션 단절과 소켓 재생성을 무한 반복하여 네트워크 버퍼 리소스를 폭발시키는 루프입니다.

➔ EAP 드라이버 단에서 소켓이 바인딩됨과 동시에 Select.req를 선제 송신(Active 역할)하도록 소켓 리셋 주기와 이벤트 동기화 보완

HSMS vs SECS-I 통신 특성 대조

현장 물리 회선 전환 결정 시 기술 참조가 되는 두 표준 계층의 정량적 비교 테이블입니다.

구분 기준 HSMS (SEMI E37) SECS-I (SEMI E4)
물리적 계층 Ethernet TCP/IP (소켓 인터페이스) RS-232C 직렬 통신 (D-Sub 9핀)
최대 속도 100 Mbps ~ 1 Gbps (대용량) 9600 ~ 19200 bps (저속 제한)
세션 상태 모델 Select / Deselect 기반 엄격한 상태 전이 ENQ / EOT 단방향 신호 핸드셰이크
전송 오버헤드 4B Length + 10B Header (매우 낮음) 1B Length + 10B Header + 2B Checksum
주요 타이머 T5, T6, T7, T8 (5초 ~ 10초 범위) T1, T2, T3, T4 (문자 간 0.5초 극단 감지)

E37 세션 제어 및 정합성 검증 의사코드 (Pseudo-code)

// ==========================================
// 함수: handleE37Event
// 목적: HSMS 프레임 헤더 분석 및 제어 메시지 정합성 검증
// 매개변수: frame (수신된 HSMS RAW 바이트 프레임 객체)
// 반환값: 에러 코드 또는 정상 처리 상태
// ==========================================
function handleE37Event(frame):
    // 1. 4바이트 길이 정보 및 10바이트 SECS 헤더 무결성 검증
    assert frame.length >= 10
    assert frame.secsHeader is not null
    
    // 2. HSMS 제어 메시지 유형(Control Type) 판별
    // 헤더의 9번째 바이트(Presentation Type)가 0인 경우 제어 메시지로 분류
    presentationType = frame.secsHeader[8]
    if presentationType == 0:
        controlType = frame.secsHeader[9] // 10번째 바이트에 Control Type 기록됨
        
        // 3. Select.req (세션 수립 요청) 수신 처리 분기
        if controlType == TYPE_SELECT_REQ:
            if currentSessionState == STATE_SELECTED:
                // 이미 세션이 수립되어 SELECTED인 경우, REJECT.rsp 송신
                sendRejectResponse(frame.systemBytes, REASON_ACT_SELECTION)
                logWarning("경고: 이미 Selected 상태이나 중복 Select.req 수신하여 거절함")
                return ERROR_DUPLICATE_SELECT
            else:
                // 정상적으로 NOT_SELECTED 상태인 경우, Select.rsp(정상:0) 송신 후 상태 전이
                sendSelectResponse(frame.systemBytes, STATUS_SUCCESS)
                transitionToState(STATE_SELECTED)
                stopTimer(T7) // T7 타이머 해제
                logInfo("성공: Select 핸드셰이크 완료 및 SELECTED 상태로 진입")
                return STATUS_SUCCESS
                
        // 4. Linktest.req (회선 헬스체크) 수신 처리 분기
        elif controlType == TYPE_LINKTEST_REQ:
            // 정상 동작 상태 대답을 위해 Linktest.rsp 반환
            sendLinktestResponse(frame.systemBytes)
            updateLastLinktestTime()
            return STATUS_SUCCESS
            
        // 5. Separate.req (세션 정상 단절 요청) 수신 처리 분기
        elif controlType == TYPE_SEPARATE_REQ:
            logWarning("알람: 호스트측으로부터 정상 세션 종료(Separate) 요청 수신")
            transitionToState(STATE_NOT_SELECTED)
            closeActiveSocket()
            return STATUS_SUCCESS
            
    // 6. 데이터 스트림 메시지인 경우 상위 SECS-II 디코더로 바이패스 전달
    else:
        if currentSessionState != STATE_SELECTED:
            // SELECTED 상태가 아닌데 데이터 전송을 시도하는 경우 거부 처리
            sendRejectResponse(frame.systemBytes, REASON_NOT_SELECTED)
            return ERROR_NOT_SELECTED
            
        publishToSecsIIDecoder(frame.payload)
        return STATUS_SUCCESS

SEMI E37: High-Speed SECS Message Services (HSMS) Generic Services
