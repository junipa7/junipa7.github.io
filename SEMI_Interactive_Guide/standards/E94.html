1장. SEMI E94 (Control Job Management) 개요

SEMI E94는 장비에 내리는 가장 최상위의 작업 지시서인 Control Job (CJ)을 관리하는 표준입니다. E40의 Process Job(PJ)이 "이 웨이퍼들을 어떻게(레시피) 구울까?"에 집중한다면, E94의 CJ는 "이 FOUP(Carrier)에 대해 어떤 PJ들을 순서대로 실행시킬까?"라는 물류와 공정의 결합을 관장합니다.

2장. Control Job의 구조와 역할

호스트(MES/EAP)가 장비에게 최종적으로 작업을 지시할 때, 최소 1개의 CJ와 1개 이상의 PJ를 묶어서 내려보냅니다.

1. 계층 구조 (Hierarchy)

하나의 CJ는 여러 개의 PJ를 소유할 수 있습니다. (1 : N 관계)

  • 예: CJ_001 (작업 대상: FOUP_A)
    • └ PJ_001 (웨이퍼 1~12번, "OXIDE" 레시피 적용)
    • └ PJ_002 (웨이퍼 13~25번, "NITRIDE" 레시피 적용)

2. 물류 제어 주도 (Carrier Management)

CJ는 시작될 때 E87의 Carrier 객체를 '예약(Reserve)'하고, 가공 중에는 FOUP을 뺄 수 없게 락(Lock)을 겁니다. 모든 PJ가 완료되어 CJ가 끝나야 FOUP 잠금을 해제(CarrierOut)하여 OHT가 가져갈 수 있게 만듭니다.

3장. Control Job 상태 모델 (State Model)

CJ 역시 생성부터 완료까지 상태 전이를 가집니다.

CJ 상태설명
Queued호스트가 CJ를 생성하고 대기 중인 상태.
Executing하위의 PJ 중 하나라도 셋업되거나 실행(Processing)을 시작하면 CJ도 Executing으로 넘어갑니다.
Paused작업 일시 정지. 하위 PJ들도 모두 Paused 상태가 됩니다.
Completed하위의 모든 PJ가 정상 완료되고, 대상 웨이퍼들이 모두 원위치(Destination)로 복귀했을 때 도달합니다.
Aborted심각한 에러나 호스트의 S14F3 (SetAttr 'Stop') 명령으로 작업이 강제 종료된 상태.

4장. 실무 적용: 작업 시작 트리거 (Start Method)

Auto Start vs Manual Start CJ를 만들 때 StartMethod 속성을 True(Auto)로 주면, 생성되자마자 즉시 가공을 시작합니다. False(Manual)로 주면 Queued 상태로 머물다가, 나중에 호스트가 명시적으로 PRJobCommand = START를 내려야 비로소 움직입니다. 장비 종류(연속 처리 장비 vs 배치 장비)에 따라 설계가 다릅니다.
Exception Recovery (복구 지시) 작업 중 알람이 발생해 장비가 멈췄을 때, CJ 레벨에서 재시도(Resume)를 할지, 현재 상태에서 그대로 작업을 포기(Abort)할지를 호스트가 결정하여 지시합니다. 이때 남아있는(미가공) 웨이퍼의 상태 처리가 매우 까다로우므로 상태도 다이어그램(State Diagram) 검증이 필수입니다.
